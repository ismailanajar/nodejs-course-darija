الـ session ديال authentication: passport callbacks + cookies + logout

عندنا user فـ database — دابا كيفاش نقولو للسيرفر "هاد الـ request جا من عندو" فالمرة الجاية؟ الجواب: serialize, cookie, deserialize.

~10 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تكمّل الـ authentication flow من الأول حتى للأخير: token فالـ cookie، req.user فكل route، و/api/logout خدام — وغادي تقدر تشرح لـclient شنو كيوقع فالخلفيات فكل request.

1 · serializeUser: من user model إلى token

الـ callback سالا الخدمة ديالو وجاب لينا user model من database — دابا بقات غير آخر خطوة: نخرّجو من هاد الـ model token صغير كيعرّف الـ user (user.id)، ونصيفطوه للـ browser فـ cookie باش يرجع مع كل request جاي. علاش هادي مهمة ملي تخدم لـclient: حيت الـ client غادي يسولك علاش الـ login كيبقى خدام بلا ما يعاود يدخل، وهاد الـ token هو الجواب.[1]

  • passport.serializeUser(fn) — الـ function هادي كتنادي أوتوماتيكياً من Passport بالـ user model اللي جيبناه، وPassport هو اللي كيحط النتيجة فالـ cookie.[1]
  • الشيطنة ديال الكود: done(null, user.id) — أول argument = error (null إلا وقع شي حاجة)، الثاني = الـ token.[1]
  • نقطة كثيرة كتلخبط: user.id ماشي هو profile ID ديال Google — هادي shortcut للـ _id اللي MongoDB ولّدو أوتوماتيكياً للrecord.[1]
  • علاش؟ حيت خدمة وحدة (Google) ماشي هي الوحيدة — ممكن تزيد Facebook ولا LinkedIn، وما تقدرش تفترض أن كلشي عندو Google ID، بصح كل user عندو ID من MongoDB.[1]

2 · deserializeUser: من token إلى user model

فكل request جاي، الـ browser كيزيد الـ cookie أوتوماتيكياً، وPassport كينادي deserializeUser بالـ token اللي فيه، والوظيفة ديالك هي تردو user model من جديد.[2]

passport.deserializeUser((id, done) => {
  User.findById(id).then(user => done(null, user));
});
  1. Google → Browser redirect لـ /auth/google/callback من بعد نجاح login
  2. Passport → cookie-session passport.serializeUser كتخرّج done(null, user.id)[1]
  3. cookie-session → Browser header ديال Set-Cookie فيه user.id ديال MongoDB
  4. Browser → Server طلب GET /api/current_user والـ cookie راجعة معاه أوتوماتيكياً
  5. Passport → Request deserializeUser كتجيب الـ user بـ User.findById(id)[2]
  6. Server → route handler req.user عامر بالـ user model فـ GET /api/current_user[4]

كيفاش تقرا هاد المخطط: كل سطر رسالة وحدة — شكون صيفط، لشكون، وشنو هو الـ artifact اللي داز بيناتهم.

تنبيه راجع الإملاء ديال serializeUser و deserializeUser — الكورس قال بزااف الناس كيديرو typo وكيوجهم خطأ "is not a function".[2]

3 · Cookies: Express ما عندها والو

  • بلا أي مكتبة زيادة، Express ما عندها حتى دعم ديال cookies out of the box.[3]
  • الحل: npm install --save cookie-session ونربطوها فـ index.js (اللي هو مكان الـ setup كامل ديال التطبيق).[3]
بأي مثال الـ cookie بحال سوارة المسبح: أول مرة كتثبت راسك عند الباب (الـ login)، كيعطوك سوارة — ومن بعد ما كيسولوكش على الوثائق من جديد، غير كيشوفو السوارة. هكذا خدام cookie-session: login مرة وحدة، ومن بعد كل request كيجيب معاها الـ cookie والسيرفر كيرجع ليك الـ user model.[3]

4 · كيفاش كيتجرّب: من cookie إلى req.user

  1. cookie-session كتحل الـ cookieالـ request ديال GET /api/current_user كيوصل، والـ middleware كتحل Set-Cookie وتجبد user.id.
  2. deserializeUser كترجّع الـ userpassport.deserializeUser كتعيّط على User.findById(id) وترد الـ user model كامل.
  3. req.user كيتلصق فوق الـ requestالـ user model كيتحط فـ req.user، ومن بعد الـ request كيدوز للـ route handler ديال /api/current_user.

كيفاش تقرا هاد المخطط: قرا الخطوات بالترتيب من الفوق للتحت — كل خطوة كتخرّج artifact كيدخل للخطوة اللي من بعدها.

  • الـ نتيجة النهائية ديال العملية كاملة هي أن الـ user model اللي رجع من deserializeUser كيتصاوب فوق الـ request بـ req.user، ومن بعد الـ request كيمشي للـ route handler ديالو.[4]
  • الطريقة ديال التجربة: route جديد GET /api/current_user غير كيرجع req.user — إلا رجع user، يعني authentication خدام.[4]
  • خاصك تعاود تدخل مرة وحدة من /auth/google من بعد ما زدتي الـ cookie logic باش يتولّد الـ cookie، ومن بعد حل /api/current_user — غادي تشوف user ديالك بالـ id، الـ Google ID، و__v ديال Mongoose.[4]
  • Logout: route GET /api/logout؛ Passport كيزيد على الـ request الـ req.user ودوال خرين، واللي همنا هو req.logout() — كتاخد الـ ID اللي فالـ cookie وكتقتلو.[5]

5 · ممارسة retrieval

جاوب من راسك قبل ما تحل شي حاجة. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو كيوقع من بعد ما deserializeUser يرجع user model؟

النتيجة النهائية هي req.user فوق الـ request، ومن بعد الـ request كيمشي للـ route handler ديالو.[4]

2. شنو كيدير req.logout()؟

الـ req.logout() كتاخد الـ cookie اللي فيها الـ user ID وكتقتل الـ ID — يعني كتخرج الـ user من التطبيق.[5]

3. علاش خاص cookie-session قبل ما Passport يخدم على authentication؟

الكورس قال باللي Express out of the box ما عندها حتى فكرة على cookies، وهادشي علاش نصبنا cookie-session.[3]

4. مراجعة: علاش كيتسجّلو جوج records بنفس Google ID إلا مشينا مباشرة لـ save()؟

رجع للدرس 4: خاصك query بـ profile ID قبل ما تصاوب record جديد، وإلا كل دخول غادي يزيد record مكرر.[6]
