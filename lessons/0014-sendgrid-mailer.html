الـ mailer: SendGrid و templates ديال survey

الـ survey واجد فـ DB، باقي غير يوصل لـ inbox ديال الناس: غادي نصاوبو Mailer class فوق SendGrid، ونربطوها بـ template ديال الـ email، ونكملو الـ route handler حتى لآخر خطوة.

~14 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقدر تصاوب أي mailing feature: class وحدة قابلة لإعادة الاستعمال (new Mailer({subject, recipients}, content))، template كتصاوب الـ HTML، وroute handler كيصيفط، كيحفظ، وكينقص الـ credit — مع error handling و الـ click tracking اللي كيخلي SendGrid يعرف شكون كي click.

1 · وين كيتسنط الـ mailer: route handler + template

الـ mailer كيتستعمل من routes/surveyRoutes.js، مباشرة بعد ما نصاوبو الـ survey instance: const Mailer = require('../services/mailer') + surveyTemplate من services/emailTemplates/surveyTemplate.[6]

الـ template هي function كتاخد الـ survey وترجع HTML string ديال body ديال الـ email (فالبداية كانت غير <div>، ومن بعد رجعناها صفحة كاملة بـ backtick string: عنوان "I'd like your input"، ${survey.body}، وجوج links ديال yes/no).[6][12]

const mailer = new Mailer(
  { subject: survey.subject, recipients: survey.recipients },
  surveyTemplate(survey)
);

والمهم: الـ survey ما كيتحفظش وحدو — خاصك تنادي بـ survey.save() يدوياً.[1] والـ mailer ماشي strictly coupled للـ survey: غير object فيه subject و recipients، وهكذا تقدر تستعملو لأي email أخرى فالمستقبل.[7]

نتيجة كتجي غلط نسيتي survey.save(): الـ email كتوصل للناس كاملين ولكن الـ survey ما كاينش فـ DB — يعني كاين links ديال yes/no على استبيان ما منسجّلش، وما تقدرش تقرا شكون صوّت. الحل: await survey.save() من بعد ما الـ send ينجح.

2 · تشريح الـ Mailer class

الملف: services/Mailer.js — class Mailer extends helper.Mail (الـ helper جاي من الـ SendGrid NodeJS module اللي كنصايبو بـ npm install @sendgrid/mail فالأخير).[3][4]

Property / methodشنو كيدير

باش كتدير click tracking؟ حيت الـ email اللي كنصيفطو كتبقى وحدة للجميع، ولكن SendGrid كتبديل كل link بـ link خاص بيها — وهكذا كتعرف شكون clicka. هادي هي النقطة اللي كلشي كيعتمد عليها.[14]

  1. Mailer → SendGrid POST /v3/mail/send مع HTML واحد للجميع
  2. SendGrid → Inbox كل link كيتبدل بـ tracking link خاص
  3. Recipient → SendGrid الـ click كيدوز عبر SendGrid قبل redirectDomain
  4. SendGrid → Activity كيتسجل click مع email ديال مولاه

3 · الـ send(): كيتصيفط لـ SendGrid

async send() {
  const request = this.sgApi.API.emptyRequest({
    method: 'POST',
    path: '/v3/mail/send',
    body: this.toJSON()          // كل الـ properties → JSON
  });
  const response = await this.sgApi.API(request);
  return response;
}

الـ toJSON() طريقة ديال base class كيحوّل كلشي لـ JSON، و emptyRequest + API(request) هي الطريقة ديال SendGrid باش تصيفط الـ request.[10] الـ send() async — يعني خاصك await عليها.[10]

  1. new Mailer(...)الـ route handler كيعطيها { subject, recipients } و HTML من surveyTemplate(survey).
  2. constructor كيعمر from_email، body، الـ recipients، و addClickTracking().
  3. send() toJSON() → emptyRequest → POST /v3/mail/send.
  4. SendGrid كتبديل كل link بـ tracking link وكتصيفط الـ email لـ inbox.
  5. recipient كيوصل الـ email، والـ click ديالو كيفتارك فـ Activity feed.

فـ SendGrid dashboard، من Activity تقدر تشوف الـ events: processed, delivered, opened، وفوق كلشي click — يعني SendGrid عارف بالضبط شكون clicka على أي email.[14]

الترتيب كيهم: خاص الـ email توصل قبل ما نسجلو الـ survey، وخصوم الـ credit واحد (req.user.credits -= 1) من بعد ما نعلمو بلي الـ send نجح، وفالأخير نرجّعو الـ user المحدّث بحال ما درنا مع Stripe.[13] وكلشي لفّف فـ try/catch — إلا وقع شي خطأ، res.status(422) (unprocessable entity) مع الـ error message.[13]

بأي مثال الترتيب بحال الحانوت: كتعطي السلعة للكليان عاد كتكتبها فالدفتر وكتاخد الثمن. إلا ما وصلاتش السلعة ما كتكتب والو وما كتنقص والو: صيفط عاد حفظ عاد نقص الـ credit.

وأول ما نختبرو، كنلقاو مشكل: الـ links ديال yes/no كيرجعو لـ localhost:3000 — ماشي مشكل فـ development، ولكن فـ email ما يمكنش تستعمل relative links (غادي يوصلو لـ domain ديال Gmail!). الحل: redirectDomain key فـ config/dev.js (http://localhost:3000) و config/prod.js (process.env.REDIRECT_DOMAIN)، والـ template كيستعملو بـ string interpolation، وكنصاوبو route GET /api/surveys/thanks كيرجع "Thanks for voting".[15]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو كيدير addClickTracking داخل الـ Mailer؟

الـ click tracking كيخلّي SendGrid تستبدل كل link بـ link خاص بيها، وهكذا تعرف شكون clicka — الـ email اللي كنصيفطو كتبقى وحدة للجميع.[8]

2. شنو الدور ديال surveyTemplate(survey)؟

الـ template function كتاخد الـ survey وترجع HTML string (عنوان + survey.body + جوج links)، أما الـ send فخدام فيها الـ mailer.send().[6][12]

3. مراجعة: من درس الـ survey model، شنو نوع relationship field _user؟

_user: { type: Schema.Types.ObjectId, ref: 'user' } — رابط لـ users collection، أما الـ Boolean الـ default false فداير على responded ديال كل recipient.[16]

4. بعد ما mailer.send() ينجح، شنو الخطوة اللي من بعد فـ route handler؟

الترتيب: صيفط → await survey.save() → req.user.credits -= 1 و await save() → res.send(user) — الـ credit كيخصم غير من بعد ما الـ send ينجح.[13]
