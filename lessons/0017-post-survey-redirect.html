تصفيط survey للسيرفر و redirect

الفورم كامل واجد — باقي غير النهاية: نصيفطو الـ values لـ /api/surveys، نجدّدو الـ credits ديال user، ونردوه للـ dashboard بلا ما يبقا واقف.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقفل الـ loop كامل ديال أي form عندك: form values → POST للـ API → update ديال store → redirect. هادي هي القطعة اللي كتقلب واجدة ديال UI لـ feature حقيقية يقدر الـ client ديالك يستعملها.

1 · scaffold ديال الـ action creator

قبل ما نكتبو المنطق، الكورس كيعاود ليك الثلاثة ديال الـ tasks اللي باقيين: شنو كيوقع ملي يclicki على send survey، كيفاش نرجّعو الـ user للـ dashboard، وكيفاش نرميو الـ values اللي بقاو مخزنين بعد ما يclicki cancel.[1]

أي تبديل فـ بيانات التطبيق = action creator، ولهذا كنصاوبو submitSurvey فـ src/actions/index.js: كتاخد values كـ argument، وترجع object فيه type (مثلا SUBMIT_SURVEY) — غير باش الـ Redux ما يطيحش، بلا منطق آلي بعدا.[1]

الربط ساهل: كدير import * as actions وكتعطيهم لـ connect كـ argument ثاني، وهكذا SurveyFormReview كتولي عندها submitSurvey كـ prop. وملي كتربطها بزر الـ send خاصك تغلّفها بـ arrow function، حيت إلا كتبتي onClick={submitSurvey(formValues)} راها غادي تخدم ملي كيبان الزر ماشي ملي كتclicki عليه. علاش هادي مهمة ملي تخدم لـclient: أي زر ديال الإرسال عند الـ client خاصو يخدم غير ملي الـ user كيclicki، ماشي قبل.[1]

onClick={() => submitSurvey(formValues, history)}
نتيجة كتجي غلط إلا كتبيتي onClick={submitSurvey(formValues)} بلا arrow function، الـ POST كينادي غير منين يتفسّر الـ render — يعني الـ survey كتتصفط والـ credits كينقصو قبل ما الـ user يclicki والو. الإصلاح: خلي النداء موقوف حتى يوقع الـ click.

2 · تصفير القيم: قطع ذكي

الـ bug: ملي الـ user يclicki cancel ومن بعد يرجع للفورم، الـ inputs معمرين بحال والو. السبب: حططينا destroyOnUnmount: false على SurveyForm. ولكن حلها ماشي بـ handler على زر الـ cancel — حيت الـ user يقدر يخرج من الفورم بأي link آخر فالـ header.[2]

الحيلة: كنربطو reduxForm({ form: 'surveyForm' }) بـ SurveyNew هو (نفس الـ اسم ديال form). النتيجة: ملي كتبدل بين SurveyForm و SurveyFormReview ما كاين unmount ديال SurveyNew → القيم كيبقاو؛ وملي الـ user يخرج من SurveyNew كامل (cancel ولا أي route آخر)، هو اللي كيunmount → الـ default behavior ديال Redux Form كيرمي القيم كاملة.[2]

باقي داخل SurveyNewالتبديل بين SurveyForm و SurveyFormReview ما كيديرش unmount ديال SurveyNew اللي عليه reduxForm('surveyForm') → القيم كيبقاو فالـ store.
خرج من SurveyNewالـ user مشا لأي route آخر (زر cancel ولا link فالـ header) → SurveyNew كيدير unmount → الـ default behavior ديال Redux Form كيرمي القيم كاملة.

كيفاش تقرا هاد المخطط: قارن الحالة بجوج — داخل SurveyNew القيم كيبقاو، خارج SurveyNew القيم كيتمسحاو.

3 · مطابقة الأسماء: من emails حتى recipients

قبل الـ POST، فاتورة صغيرة: الـ backend ديالنا (اللي كتبناه من قبل) كيتسنا req.body.recipients، أما الفورم فكايمتّل emails — تناقض بين الطرفين. التصليح ساهل: تبدل name فـ file ديال الـ fields، ومن بعد errors.recipients و values.recipients فـ الـ validate function.[3]

4 · POST → dispatch → redirect

الآن المنطق حقيقي فـ submitSurvey، نفس الطريقة ديال handleToken:

export const submitSurvey = (values, history) => async dispatch => {
  const res = await axios.post('/api/surveys', values);
  dispatch({ type: 'fetch_user', payload: res.data });
  history.push('/surveys');
};
  1. SurveyFormReview → submitSurvey submitSurvey(formValues, history) من الـ props
  2. submitSurvey → axios POST /api/surveys بـ values
  3. Express → MongoDB handler ديال POST /api/surveys: خصم credit و save ديال survey
  4. Express → submitSurvey res.data = user مجدّد مورا خصم credit
  5. submitSurvey → Redux store dispatch fetch_user → header كيجدّد الرصيد
  6. submitSurvey → react-router history.push('/surveys')

كيفاش تقرا هاد المخطط: تبع الأرقام من 1 حتى 6 — كل سطر رسالة من جهة لجهة مع الـ artifact اللي مشات فيها.

  • الـ POST /api/surveys كيرجع الـ user model المجدّد (اللي خصّم من الـ credits)، ولهذا كنـ dispatch بو fetch_user — وهكذا الـ header كيupdate بـ الرصيد الجديد بلا refresh.[4]
  • الـ اختبار فالكورس: POST كيرجع 200، الـ credits نقصو من 7 لـ 6، والـ email وصلات لـ inbox ديال الاختبار.[4]
  • الـ redirect مشيال: الـ Link غير لـ clicks، وهنا بغيتي programmatic navigation من داخل الـ action creator. المسالة: SurveyNew هو اللي كيعرف react-router (Rendered by route)، أما SurveyFormReview ولا الـ action creator لا. الحل: withRouter من react-router-dom — function كتلبس الـ component بحال connect ولكن بتوقيع مختلف: withRouter(SurveyFormReview).[5]
  • من بعد، الـ history object كيجي مع الـ props، كديروه كـ argument الثاني للـ action creator، وتستعملو history.push('/surveys') من بعد ما يكمل الـ request بنجاح.[5]

الكورس كينبّه: فالـ versions القديمة ديال react-router هاد الشي كان أسهل؛ فالنسخ الجديدة خاصك withRouter + تمرير history يدويا.[5]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. علاش غلفتي submitSurvey(formValues) بـ arrow function فـ onClick؟

onClick={submitSurvey(formValues)} كيبان بـ call expression — كينادى فور ما يتفسّر الـ render. الـ arrow function كتحوّلو لـ deferred call.[1]

2. مراجعة: من الدرس 16، شنو اللي كيخلي الـ review يقرا الـ values ديال الفورم؟

الـ mapStateToProps كيرجع state.form.surveyForm.values كـ prop — نفس الطريق ديال أي React Redux component.[2]

3. علاش كنـ dispatch({ type: 'fetch_user' }) من بعد الـ POST؟

الـ route handler كيرجع الـ user model بعد ما خصّم credit؛ الـ dispatch كيجدّد الـ auth state فالـ store، والـ redirect خدمة أخرى (history.push).[4]

4. علاش بدّلنا اسم emails بـ recipients فالـ client؟

الـ API اللي كتبناه من قبل كيقرأ req.body.recipients — إلا ما سماوحتش الـ client بنفس الـ اسم، الـ field غادي يكون undefined فالسيرفر.[3]
