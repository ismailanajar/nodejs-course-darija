2 · subdocument ولا relationship field؟

القرارمتىفهاد الـ app
subdocumentالسجل ما عندو معنى بلا والد ديالو (ownership واضح).recipients داخل survey.[5]
relationship fieldالسجل عندو معنى بلا والد، ولا الـ parent يقدر يتكبر بلا حدود.survey → user (_user).[5]
  • 4MB = limit ديال document وحدة فـ MongoDB. بـ ~20 bytes للـ email → وحدة survey ≈ 200,000 recipients.[5]
  • إلا حطينا surveys كاملة داخل user → نفس الـ limit كيطبّق على user كامل → super user كيوقف فاش يستهلك 200k.[5]
  • بناءً على هادشي: recipients = subdocs، surveys = collection وحدة مع _user.

5 · send() + template + redirect

async send() {
  const request = this.sgApi.API.emptyRequest({
    method: 'POST',
    path: '/v3/mail/send',
    body: this.toJSON()
  });
  const response = await this.sgApi.API(request);
  return response;
}
  • الـ template: services/emailTemplates/surveyTemplate.js — function كترجع HTML (backtick string): عنوان، ${survey.body}، وجوج links ديال yes/no.[15]
  • الـ links: ماشي relative (فـ inbox غادي يوصلو لـ domain ديال Gmail) — كيستعملو keys.redirectDomain + /api/surveys/thanks (route كيرجع "Thanks for voting").[16]
  • التحقّق: من SendGrid dashboard → Activity → events ديال processed / delivered / opened / click — الـ click هو اللي كيخلي الـ feedback يرجع.[17]
  • الاختبار: POST مع login + credits (test card 4242) بلا ما تصاوب شي UI.[18]
