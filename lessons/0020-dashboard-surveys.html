الـ dashboard: جلب و عرض قائمة surveys

آخر ميزة كبيرة فالتطبيق: user كيفتح الـ dashboard خاصو يشوف قائمة ديال surveys اللي صاوب هو بوحدو — من الـ route ديال Express، مرورا بـRedux، حتى لـcards فـReact. هاد الدرس كيجمع الطريق كاملة اللي تعلمناها.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تسد الدورة كاملة: GET /api/surveys مقصور على المستعمل الحالي، response خفيف بلا الـ recipients، action creator + reducer فـRedux، و SurveyList كتقلب الـ JSON لـcards مرتبة بالجديد فوق.

1 · الـ backend: غير surveys ديالي

الطلب واضح: ملي user يفتح الـ dashboard، خاص الـ React يدير request للـ API ويجيب غير الـ surveys اللي صاوبها هو — ماشي الكل.[1] المكوّنات:[1]

  • الـ route: app.get('/api/surveys', requireLogin, handler) — المستعمل الحالي كيتحط من passport فوق req.user، وحنا خاصنا نتأكدو أن اللي طالب مسجل دخول (نفس الـ middleware ديال requireLogin اللي كنستعملوه من زمان، كنديروه ثاني argument للـ handler).[1]
  • الـ survey model عندو خاصية _user فيها الـ ID ديال اللي صاوب الـ survey — داكشي علاش الاستفسار هو Survey.find({ _user: req.user.id }).[1]
  • الـ query غير تنينة: const surveys = await Survey.find(...) و res.send(surveys) — وعليه async على الـ handler.[1]

المشكلة اللي كيبان من تاني: كل survey كيجيب معاها الـ recipients ديالها — وممكن يكونو آلاف. الـ mockup ديالنا أصلا ما كيعرضش أسماء الأفراد، وماشي معقول نصيفط عشرات الميغا باش نعرض عدد ديال cards.[2]

2 · whitelist: .select({ recipients: false })

الحل كاين فالـ docs ديال Mongoose: Survey.find() كترجع query object تقدر تسلسل عليها .select() — وسميتها فالـ docs هي projection، يعني كتختار شنو يدخل وشنو يتحيد من النتيجة. علاش هادي مهمة ملي تخدم لـclient: الـ client ما غاديش يخلص على صفحة كتعطل حيت صيفطتي ليه ميغات زايدة ما محتاجهاش.[3] كاين جوج syntax (سلسلة بـ-fieldname ولا object بـ1/0)، وحنا استعملنا object:

const surveys = await Survey
  .find({ _user: req.user.id })
  .select({ recipients: false });

يعني: ما تعطينيش الـ recipients ملي تجيب ليا الـ surveys.[3]

الاختبار: من الكونسول ديال المتصفح (وانت مسجل دخول) axios.get('/api/surveys') — خاصك ترجع 200، وفالـ Preview غادي تشوف كل survey بـbody، dateSent، lastResponded، no، yes، subject و title — بلا حتى email.[4]

  1. axios → Express GET /api/surveys مع requireLogin
  2. Express → MongoDB Survey.find({ _user: req.user.id }).select({ recipients: false })
  3. MongoDB → Browser res.send(surveys) بلا recipients

كيفاش تقرا هاد المخطط: تبع الأرقام من 1 حتى 3 — الطلب كيمشي من الـ browser للـ DB وكيخرج خفيف بلا recipients.

3 · نوصّلو الـ data بـRedux

نفس الدورة اللي كنعاودوها من البداية ديال الكورس:[5]

  • type: export const FETCH_SURVEYS = 'fetch_surveys' فـactions/types.js.[5]
  • action creator: fetchSurveys() — ماعندو حتى argument، كيدير await axios.get('/api/surveys') ومن بعد dispatch({ type: FETCH_SURVEYS, payload: res.data }) (الـ payload هو array ديال الـ surveys).[5]
  • reducer: surveysReducer جديد — الـ state الافتراضي ديالو array خاوية (يعني ملي يحل التطبيق الـ surveys كيولّيو خاويين)، وكيجاوب على FETCH_SURVEYS بـreturn action.payload.[5]
  • combineReducers: نزيدوه بـsurveys: surveysReducer — وهاد هو السبب علاش من بعد كنقراو state.surveys.[5]
نتيجة كتجي غلط إلا صاوبتي surveysReducer وما سجلتيهش فـcombineReducers، state.surveys غادي يبقى undefined — والـ SurveyList كتطيح فـconsole بـCannot read property 'map' of undefined وبلا حتى بطاقة. الإصلاح: سجّلو بـsurveys: surveysReducer وتأكد أن الـ state الافتراضي هو array خاوية.

4 · React: مكوّن منفصل + cards

قرار تصميم مهم: الـ Dashboard ما خاصوش يتكلف بالجلب ولا بالعرض. حنا صاوبنا مكوّن جديد components/surveys/SurveyList.js — هو اللي كيجيب وكيعرض، والـ Dashboard غير كيفتّحو.[6] داخل SurveyList:[6]

  • connect(mapStateToProps, { fetchSurveys }) — الـ mapState غير كيرجع state.surveys (بـshorthand: { surveys }).[6]
  • componentDidMount() فيه this.props.fetchSurveys() — أي ملي المكوّن يتعرض للمرة الأولى.[6]
componentDidMount→ fetchSurveys()→ GET /api/surveys→ dispatch FETCH_SURVEYS→ surveysReducer→ state.surveys
الـ SurveyList كتعاود تrender بالـ cards الجديدة

كيفاش تقرا هاد المخطط: تبع الأسهم فالدائرة — SurveyList كتنادي fetchSurveys و state.surveys الجديدة كتعاود ترسم الـ cards.

العرض: HTML ديال Materialize cards — ماشي الـ divs ديال row و col اللي كيقدرو يضيّقو العرض، غير من card ... لتحت. لكل survey وحدة:[7]

this.props.surveys.map(survey => (
  <div key={survey._id} className="card darken-1">
    <div className="card-content">
      <span className="card-title">{survey.title}</span>
      <p>{survey.body}</p>
      <p className="right">Sent on: {new Date(survey.dateSent).toLocaleDateString()}</p>
    </div>
    <div className="card-action">
      <a>Yes: {survey.yes}</a><a>No: {survey.no}</a>
    </div>
  </div>
))
  • key={survey._id}: داخل الكونسول ديال React والـ raw Mongo خاصك _id (الـ id النظيفة هي ديال Mongoose).[7]
  • التاريخ: ملي يجي من الـ DB للمتصفح كيولي string خام (ماشي Date object) — داكشي علاش new Date(survey.dateSent).toLocaleDateString().[7]
  • الـ yes/no: استعملنا <a> باش ناخذو الـ styling ديال Materialize مع أن هادي ماشي navigation حقيقية (hack صغيّر مقبول هاد المرة).[7]

الترتيب: الـ surveys كيجيو بالأقدم فوق — باش الجدد يبانو فوق، زدنا .reverse() قبل ما نـmapو (بلا ما نبدّلو الـ array الأصلية بـsort). وباش النموذج يبدو حيو، بدّلو الـ vote counts يدويا من الـ MongoDB UI.[8]

النشر: git status → git add . → git commit -m "users can see survey results" → git push heroku master. وتذكير مهم: الـ webhook ديال SendGrid باقي كيشير للـ tunnel ديال laptop ديالك — والـ SendGrid ما كيقبلش جوج webhooks فـحساب واحد، ف إلا بغيتي كلشي خدام فـproduction خاصك تبدّل الـ URL ولا تدير حساب ثاني.[9]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki.

1. علاش زدنا .select({ recipients: false }) على الـ query؟

الـ dashboard غير كيعرض counts و titles — والـ recipients ممكن يكونو آلاف لكل survey. الـ projection هي اللي كتمنع النقل ديال البيانات اللي مامستعمليناش.[3]

2. وين بالضبط خاصك تبدّل الـ webhook URL ملي بغيتي يخدم فـproduction؟

الـ Event Notification هو اللي كيحدد فين يصيفط SendGrid الـ events — والـ tunnel ديال الـ dev باقي كيشير للـ laptop، فخاصك الـ URL ديال الـ app المنشورة.[9]

3. شنو كيدير componentDidMount() داخل SurveyList؟

الـ lifecycle method كتنادي this.props.fetchSurveys() أول ما المكوّن يتعرض — وهاد هو الدافع اللي كيحيّي الـ request ديال GET /api/surveys.[6]

4. مراجعة: علاش خاص الـ query ديال webhook تبقى كتخدم من داخل Mongo بلا نقل البيانات؟

البحث و التسجيل داخل Mongo بزاف أسرع من نقل الـ survey كامل للـExpress، تعديلو، ومن بعد ترجعي ترسلو — داكشي علاش استعملنا updateOne.[10]
