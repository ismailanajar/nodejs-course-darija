من webhook لنتائج: lodash chain و mongoose queries

دابا عندنا أحداث نظيفة داخل req.body — باقي غير نقصو الـ duplicates، ونعلمو الـ survey بالـ vote، وبشكل ما يشدش الـ DB ديالنا فـمئة ديال الرسائل. هاد الدرس هو ديك اللحظة اللي كيتحول فيها الـ webhook لـnumbers حقيقية.

~13 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تكتب updateOne وحدة كتدير البحث و التسجيل كامل من داخل Mongo ($inc + $set)، وكتعرف علاش find + save هي بالضبط اللي ما خاصكش دير. النتيجة: vote واحد لكل شخص، مهما clicka عشر مرات.

1 · من الأحداث القذرة لـchain نظيف

قبل ما نلمسو الـ DB، خاصنا ن assureو أن كل event اللي غادي ندخلوه هو surveyId + email + choice صحيحة. الخطوات:[1]

  • _.compact(events) — كيحيّد كل الـ undefined اللي خلا الـ map ملي لقى event ديال نوع bounce ولا URL ماشي ديالنا.
  • _.uniqBy(events, 'email' + 'surveyId') — كيحيّد الـ duplicates، ولكن بشرط: نفس الـ email فجوج surveys مسموح (user وحيد يصوّت فجوج campaigns)، غير نفس الـ email على نفس الـ survey هو الممنوع.[1]

نقطتين فالـ code:

  • خرج const p = new Path(...) من داخل الـ map — ماشي خاصك تصنع path helper جديد فكل iteration.[2]
  • عاود جاوب على SendGrid — إلا ما صيفطتيش response ناجح، الـ SendGrid كيعتبر الـ request فاشل وكيعدّل نفس الـ event مرة من بعد مرة (وهو سبب الـ duplicates اللي كتشوف فالـ logs).[1]

ومن بعد، بدّل المتغيرات المؤقتة (events، compactEvents، uniqueEvents) بـسلسلة وحدة:[2]

const events = _.chain(req.body)
  .map(event => { /* pathname + p.test + return object */ })
  .compact()
  .uniqBy('email', 'surveyId')
  .value();

الفائدة ماشي غير ديال النظافة: أي مهندس كيقرا السلسلة كيشوف المسار كامل (map → compact → uniqBy → value()) بلا ما يتبع متغيرات وسطية.[2]

2 · علاش find + save هي Approach الخايب

الكورس عطانا مثال ديال "كيفاش ما تديرش": نجيبو الـ survey كامل، ندورو على الـ recipients بنفرنا فـNode، نبدّلو responded، ومن بعد save() نيشان.[3] المشاكل:

  • نقل بيانات بزاف: كل survey ممكن عندو مئات ولا آلاف الـ recipients — كنجيبوهم كاملين وحنا مهتمين بوحد غير.[3]
  • نقلهم مرة أخرى: الـ save() كترجع تسجل الـ survey كامل بما فيه الـ recipients كاملين، يعني نفس النقل ديال البيانات مرة خرا.[3]
  • البحث على ضو: كندورو يدويا على array فـNode فبلا ما نخلي Mongo يدير البحث ديالو — والبحث فـMongo بزاف أسرع من نقل البيانات للـ Express ومن بعد تحليلها.[3]

القاعدة: قلّل حجم البيانات اللي كتخرج من الـ DB، وخلي البحث و التسجيل كيتشرّفو كاملين من جيهة Mongo.[3]

3 · query وحدة: updateOne + Mongo operators

الفكرة: بدل ما نجيبو و نسجلو، نستعملو Survey.updateOne(criteria, update) — الـ object الأول كيقول شكون، والتاني كيقول شنو يبدّل، والجوج كيتطبّقو من داخل Mongo بلا ما الـ survey يجي لعنّا أصلا.[4]

find + saveكنجيبو الـ survey كامل بـ find مع كل الـ recipients، كندورو عليهم بـloop فـNode، ومن بعد save() كترجع ترسل نفس القائمة كاملة للـ DB.
updateOne + $incSurvey.updateOne وحدة: الـ criteria فيها _id + $elemMatch: { email, responded: false }، والـ update فيها $inc: { [choice]: 1 } و $set: { 'recipients.$.responded': true } — كاملة من داخل Mongo.

كيفاش تقرا هاد المخطط: قارن العمودين — find + save كتجر البيانات للـ Node، و updateOne كتخلي البحث والتسجيل داخل Mongo.

Survey.updateOne(
  {
    _id: surveyId,
    recipients: { $elemMatch: { email, responded: false } }
  },
  {
    $inc: { [choice]: 1 },
    $set: { 'recipients.$.responded': true, lastResponded: new Date() }
  }
).exec();

نشرح القطعة:

  • ثلاث معايير: الـ _id خاصو يوافق الـ survey، وخاص يكون عندو recipient بنفس الـ email و responded: false. إلا الـ user صوّت من قبل، الـ criteria ما كتمشيش و كتوقف — وهاد هي الحماية ديال vote واحد.[5]
  • $inc: { [choice]: 1 }: operator ديال Mongo كيزيد yes ولا no بواحد. الأقواس المربعة ما كتصنعش array — هي key interpolation: قيمة choice كتولي هو اسم الـ property وقت التنفيذ.[6]
  • 'recipients.$.responded': true: الـ $ كيشير للـ نفس العنصر اللي ت matched فـ$elemMatch اللي فوق — يعني غير الـ recipient المعني، ماشي الكل.[6]
  • _id ماشي id: داخل استفسارات Mongo الخام خاصك _id؛ الـ id الحلوة هي ديال Mongoose اللي كتجلس فوق.[7]
  • .exec(): الـ query مكتتباش غير كتتركب — خاصك تبعدها للـ DB بـexec().[7]
نتيجة كتجي غلط إلا حيّديتي responded: false من الـ criteria (ولا رجعتي لـfind + save العمياء)، نفس الشخص يقدر يعاود clicka ويزيد نفس الـ vote مرة خرا — والعدّاد كيطلع مضلّل. الحماية هي $elemMatch: أول مرة كيتبدل responded لـtrue، ومن بعد الـ query كتوقف وحدها.

ومن بعد نزيدوها فسلسلة ديالنا فـ.each() مع destructuring: .each(({ surveyId, email, choice }) => { ... }).[7]

نتيجة كتجي غلط ما تحطش async/await على هاد الـ query. السبب: حنا مامسهغلينش نجاوبو الـ SendGrid على محتوى — غير نجاوبوه 200 باش يسالي. الـ query كتمشي فالخلفية وحنا كنكملو، ماشي خاصنا نتسناوها قبل ما نجاوبو.[7]

4 · التحقق، وآخر جوج تفاصيل

الطريقة ديال التحقق: دوز survey جديدة بجوج emails، clicka بزاف مرات على نفس الزر، ومن بعد حل الـ MongoDB UI وتأكد:[8]

  • رقم الـ votes واحد غير على الرغم من المرات الكثيرة اللي clickiti.[8]
  • غير الـ recipient اللي صوّت عندو responded: true، والباقي false.[8]

الملاحظة ديال الـ dashboard كتبان بوحدها: وحدين اللي عندو true هو dev email. باش تعاود تختبر بلا ما تصاوب survey جديد، غير بدّل responded لـfalse يدويا وسجّل.[9]

وآخر جوج حوايج:[9]

  • زيد lastResponded: new Date() داخل نفس الـ $set (خاصك تستنى جوج ثواني بعد الـ vote باش تشوفو، وإلا رجع بدّل نفس الـ survey وتستنى survey جديدة).
  • الـ link ديال الـ email دابا كيمشي لـ/api/surveys/:surveyId/:choice — داكشي علاش صفحة الـ thanks كترجع Cannot GET. الحل: route Express بنفس الـ wildcards كيرجع "Thanks for voting".[9]

وملي توحل فـ query معقدة ديال Mongoose: قلب فـGoogle هو اللول (تقريبا كل عملية عندها جواب واجد فـStackOverflow)، ومن بعد جربها فـNode REPL — حل node، لصق الـ models، وجرب Survey.find({...}).then(console.log) باش تشوف النتيجة فالبلاصة بلا ما تعاود تشغل السيرفر كل مرة. علاش هادي مهمة ملي تخدم لـclient: الـ client كيخلص على الحل السريع، ماشي على الساعات اللي ضيعتي وانت كتعاود التشغيل.[10]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki.

1. علاش الـ approach ديال find ثم تعديل ثم save تعتبر خايبة هنا؟

المشكلة هو النقل: كتجيب الـ survey كامل بما فيه كل الـ recipients (مئات ولا آلاف)، كتبحث بنفرنا فـNode، ومن بعد save() كترجع ترسل نفس القائمة كاملة للـ DB.[3]

2. شنو كيدير $ داخل 'recipients.$.responded'؟

الـ $ هي placeholder ديال نفس العنصر اللي لقاه $elemMatch — يعني غير الـ recipient اللي عندو email المطلوب و responded: false.[6]

3. شنو كيدير $inc: { [choice]: 1 }؟

$inc = increment بـ1. والأقواس المربعة key interpolation: إلا كان choice = 'yes' كتولي { yes: 1 }، وإلا 'no' كتولي { no: 1 } — ماشي array.[6]

4. مراجعة: شحال من مرة تقريبا كيصيفط SendGrid batch ديال الأحداث؟

الـ SendGrid كيجمع الأحداث وكيصيفط bulk واحد كل شي كاع 30 ثانية ولا دقيقة — داكشي علاش الـ req.body ديالنا array ديال objects.[11]
