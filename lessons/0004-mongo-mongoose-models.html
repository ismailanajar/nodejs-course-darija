MongoDB و Mongoose: connection + models + queries

الـ OAuth رجع بيك بـ profile ديال الـ user — دابا خاصنا مكان نخزّنوه فيه، وهاذاك هو MongoDB مع Mongoose.

~10 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تصاوب model ديال User، تسجّل أول user من الـ OAuth flow، وتعرف كيفاش تسول بـ profile ID باش ما يتعملوش records مكررين — بالضبط اللي كيفرق ما بين demo وتطبيق خدام لـclient.

1 · علاش خاصنا database أصلا؟

القاعدة الأولى هي الـ HTTP stateless: السيرفر كينسى كلشي بين request وrequest — ما كيعرفش شكون صيفط ولا شنو وقع من قبل.[1] يعني بلا database كل دخول جديد كيبدا من الصفر وما كيبقى حتى أثر.[1] علاش هادي مهمة ملي تخدم لـclient: حيت غادي تفهمو علاش بلا تخزين ما كاين حتى login خدام.

وفالحالة ديالنا: الكورس أولاً فسّر sign-in بـ email + password باش نفهمو المبدأ، ومن بعد دار pivot للـ OAuth flow — نفس المبدأ بس غير الطريقة كتبدل.[2]

2 · فين كنحطو الكود و فين كنحطو الداتا؟

  • ما كاين حتى convention قوي فـ community ديال Express على تنظيم المشاريع — الكورس عطى طريقة خدامة معانا: config (API keys وإعدادات)، routes (ملف لكل مجموعة ديال routes)، وmodels.[3]
  • الهدف: كل ما شي حد دخل عبر الـ OAuth، نصاوبو record واحد ديالو فـ database.[4]
  • MongoDB عندك جوج طرق: تنصب نسخة محلية على laptop ديالك، ولا تستعمل instance مستضافة عند طرف ثالث. الكورس اختار الثانية حيت التنصيب المحلي ممكن يوقع فيه مشاكل (و"real pain" بحسب الكورس).[5]
LOCAL · محليةكتنصب نسخة MongoDB على laptop ديالك — بحسب الكورس، التنصيب ممكن يوقع فيه مشاكل ويكون "real pain".
REMOTE · مستضافةinstance عند طرف ثالث بلا تنصيب على جهازك — هادي هي اللي اختارها الكورس وحنا تبعناها.

كيفاش تقرا هاد المخطط: قارن العمودين — محلي مقابل مستضاف وشوف علاش اخترنا الثاني.

3 · Connection: Mongoose → Mongo

npm install --save mongoose

من بعد فـ index.js، فـ أعلى الملف وتحت مباشرة ديال require ديال Express، كنبنو Mongoose ونديرو الـ connection — قبل ما نعرفو الـ app object.[6]

4 · Model → save → query

  1. نصاوبو models/user.js (جديد folder + file)، نطلبو mongoose من فوق، ومن object ديالو نجيبو schema.[7]
  2. الـ model class كيمثّل collection كاملة ديال records فـ Mongo.[7]
  3. الـ save كيوقع فـ Google strategy callback، اللي عندو accessToken، refreshToken و profile — والـ profile فيه الـ Google user ID اللي باغين نخزّنو.[8]
  4. المشكل: إلا درتي new User().save() بلا سؤال، كل مرة الـ user يدخل كيتسجّل record جديد بنفس الـ Google ID.[9] الحل: قبل ما تصاوب جديد، سول واش شي حد عندو نفس الـ profile ID.[9]
  5. الـ query فـ Mongo asynchronous → كترجع promise، وعليها .then(existingUser => ...). الـ existingUser يا مثيل (instance) ديال الموديل يا null.[10]
  6. فالأخير كتنادي done(...) باش تفوّت النتيجة لـ Passport.[10]
لقيتيه · existingUserكترجع نفس الـ record بـ done(null, existingUser) — بلا ما تصاوب جديد.
null · ما لقيتيهشكتصاوب جديد بـ new User({ googleId }).save() ومن بعد done(null, user).

كيفاش تقرا هاد المخطط: قارن الحالتين — إلا لقيتي الـ user استعملو وإلا صاوب جديد.

نتيجة كتجي غلط إلا درتي new User().save() نيشان بلا ما تسول، كل مرة الـ user يدخل كيتسجّل record جديد بنفس الـ Google ID — وفالـ database كتلقى نسخ مكررين من نفس الشخص. الحل: قبل أي save، سول بـ User.findOne({ googleId: profile.id }) — إلا رجع لك record استعملو، وإلا رجع null برك تصاوب جديد.

5 · ممارسة retrieval

جاوب من راسك قبل ما تحل شي حاجة. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو خاصك تعمل قبل ما تصاوب user جديد فـ MongoDB؟

الكورس شاف problem ديال جوج records بنفس الـ Google ID، والحل هو query قبل ما تصاوب record جديد.[9]

2. فين خاص mongoose.connect يتزاد؟

الكورس حط الـ connection فـ أعلى index.js وتحت مباشرة ديال require ديال Express، قبل تعريف الـ app.[6]

3. علاش الكورس اختار MongoDB مستضاف عن بعد ماشي محلية؟

الكورس قال باللي التنصيب ديال MongoDB محلي ممكن يوقع فيه مشاكل ويكون "a real pain"، وهادشي علاش استعملنا instance مستضافة عند طرف ثالث.[5]

4. مراجعة: شنو كيدير clientID فـ Google strategy؟

رجع للدرس 3: الـ clientID هو public token غير كيعرّف التطبيق ديالنا عند خدمة Google OAuth.[11]
