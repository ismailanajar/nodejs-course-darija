الـ validation و الـ wizard ديال form

فورم بلا validation = سيرفر كيرفض الإرسال فالأخير؛ وفورم بلا مراجعة = user متوتر. غادي نديرو validation عمومي + صفحات form → review بقيم كيبقاو.

~14 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تصاوب validation وحدة كتخدم مع أي حقل (validate(values) كترجع errors object)، وwizard ديال SurveyForm → SurveyFormReview بزر الرجوع اللي كيحافظ على الـ values. هادي هي الصورة اللي كيطلبها client: الفورم ما كيتحرّكش للخطوة الجاية وإلا كان شي حاجة خايبة.

1 · الأول: الفورم خاصو يبان محترم

قبل الـ JavaScript، تصليح الشكل: الـ div اللي فـ App.js كيزيد container class ديال materializeCSS — كتزيد padding من الستين وهكذا الفورم ما كيملاش الصفحة كاملة.[1]

الـ زر ديال التالي بدل submit بـ next (حيت باقي كاين مرحلة مراجعة)، بـ classes teal btn flat right white-text و icon ديال done. والـ زر ديال cancel هو Link من react-router-dom راجع لـ /surveys (الـ dashboard)، بـ classes red btn flat white-text.[1]

2 · validate: قاعدة وحدة لكل حقل

الـ option اللي كتزيد فـ reduxForm({ form, validate }) هو function كتُنادى آليا ملي الـ user يclicki على submit. توقيعها بسيط: كتاخد values object (نفسو اللي كنشوفو فـ console.log) وكترجع errors object.[2]

function validate(values) {
  const errors = {};
  if (!values.title) errors.title = 'You must provide a title';
  return errors;
}

القاعدة: إلا كان الـ errors فارغ، الـ form صحيحة وكتمشي للإرسال; وإلا كان فيه شي property، Redux Form كيوقّف الـ submission وكيعرف بلي شي حاجة ناقصة.[2]

errors فارغvalidate(values) رجعات errors = {} — الـ form كتمشي لـ onSurveySubmit وما كيبان والو.
errors فيه keyerrors.title = 'You must provide a title' — الـ submit كيحبس وSurveyField كتوري meta.error ملي meta.touched بـ red-text.

كيفاش تقرا هاد المخطط: قارن الحالتين — شوف شنو رجعات validate وشنو وقع للـ submit من بعد.

الربط بين الـ error والـ حقل كيوقع بالـ اسم: الـ key ديال الـ error خاصو يتطابق مع الـ name ديال الـ Field، ومن بعد كتاخد meta.error و meta.touched داخل SurveyField باش توري الرسالة تحت الحقل.[3] الـ تصليح ديال الرسالة: <div class="red-text"> مع margin-bottom: 20px.[3]

3 · تحقق من الـ recipients: split و regex

الـ Recipient List ماشي email وحدة — هي string طويلة فيها فواصل بحال a@b.com, c@d.com. الخدمة فـ validate كتمشي بثلاثة خطوات صغار: split(',') باش تولي list، وtrim() باش تحيد الفراغات، ومن بعد regex ديال الـ email باش تحبس اللي خاسر وتزيدو فـ errors.emails. علاش هادي مهمة ملي تخدم لـ client: حيت الـ client كيلصق list طويلة من Excel، والـ form خاصها تقول ليه بالضبط شكون خاسر بلا ما تضيع ليه اللي صحيح.[4]

ملاحظة عملية: الـ regex اللي فيه escape chars كيوقّف ESLint ديال Create React App بـ warning. الحل اللي جاب الكورس: تستعمل الـ HTML5 validation regex من emailregex.com اللي ما عندوش نفس المشكل.[4]

4 · الـ wizard: form → review بقيم كيبقاو

القرار: component-level state داخل SurveyNew سميت showFormReview (كتبدا بـ false). الـ component عنده renderContent(): إلا true كيرجع SurveyFormReview (functional component)، وإلا لا كيرجع SurveyForm.[5]

التبديل كيوقع بـ callback: onSurveySubmit كتديرو لـ SurveyForm فـ handleSubmit، والـ body ديالو كينادي this.setState({ showFormReview: true }). تنبيه مهم: كتعطيه المرجع بلا قوسين — إلا حطّيتي () كينادى مباشرة فـ render.[5] وفالجانب الآخر، onCancel كيرجع showFormReview لـ false.[6]

  1. البداية: SurveyFormSurveyNew فيه showFormReview: false وrenderContent() كيرجع <SurveyForm>.
  2. next كيقلب الواجهةonSurveySubmit بلا () كيدخل فـ handleSubmit وكينادي setState({ showFormReview: true }).
  3. SurveyFormReviewrenderContent() كيرجع <SurveyFormReview> وكيقرا state.form.surveyForm.values بـ formValues.
  4. cancel كيرجع للورonCancel كيرجع showFormReview لـ false والقيم باقين بـ destroyOnUnmount: false.

كيفاش تقرا هاد المخطط: قرا الخطوات بالترتيب — كل خطوة فيها شنو كيرجع render وشنو وقع للـ state.

باش الـ values ما تتمسحش ملي كتمشي من SurveyForm للـ review، كنزيدو destroyOnUnmount: false — لأن Redux Form كترمي القيم ملي الـ component يunmount، وهادي default عندها.[7] أما شكون كيقرا القيم فالـ review: connect و mapStateToProps كيرجعو state.form.surveyForm.values كـ prop اسمو formValues.[7]

نتيجة كتجي غلط نسيتي destroyOnUnmount: ملي كتمشي للـ review وترجع بالـ cancel كتلقى الـ form خاوية حيت Redux Form رمات القيم ملي الـ SurveyForm تحيد من الشاشة. الحل: زيد destroyOnUnmount: false وخلي نفس الـ form name فالبلاصتين.

الـ review نفسو ما كيكرر والو: الـ fields خرجناهم لـ formFields.js (نفس الـ array اللي كيستعملها SurveyForm)، والـ review كي loop عليها ويوري label + قيمة.[8] وأخيرا زر send survey (green, flat, right + icon ديال email) هو اللي خاصو يصيفط — وتلاتة ديال الـ tasks باقيين: شنو كيوقع فالـ submit، كيفاش نرجعو للـ dashboard، وكيفاش نرميو الـ values بعد ما الـ user يclicki cancel.[9]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو كيرجع الـ validate(values) function ديال redux-form؟

الـ errors object فارغ = form صحيحة؛ ملي كيكون فيه key، Redux Form كيوقّف الـ submit والـ key كيتقارن مع الـ name ديال الـ Field.[2]

2. مراجعة: من الدرس 15، منين كيجيو labels ديال الـ fields فـ SurveyField؟

الـ FIELDS array فيها label و name لكل حقل، و_.map كيدوزهم كـ props للـ Field.[5]

3. شنو أول خطوة كتاخد مع الـ string ديال الـ emails قبل ما تvalidi كل عنصر؟

split → trim → regex: الـ string كتتفكك لقائمة، ومن بعد كنتحققو من كل email وحدها.[4]

4. علاش الـ values كيبقاو ملي كتدوز من SurveyForm لـ SurveyFormReview؟

Redux Form كترمي القيم بال-default ملي يunmount الـ component؛ destroyOnUnmount: false كتبقّاهم، ونفس الـ form: 'surveyForm' هو اللي كيخليهم فـ slice وحدة.[7]
