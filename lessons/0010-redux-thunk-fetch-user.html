Redux Thunk و fetchUser: جلب currentUser و redirects

أول API call من الـ client: fetchUser كتمشي لـ /api/current_user، الـ reducer كيرجع null / false / user model، والـ header كيتبدّل — وعقب التسجيل كنوجدو redirect ديال بصح.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تفهم علاش Redux Thunk كيسمح للـ action creators يرجّعو functions، وتكتب fetchUser بـ async/await، وتقرأ دورة الـ three auth states (null/false/user) من reducer حتى للـ header، وتعرف الفرق بين redirect ديال login و logout.

1 · Redux Thunk: كسر قانون الـ action

القانون ديال Vanilla Redux: كل action creator خاصو يرجع action بشكل فوري — object فيه type وعمليا payload. ولكن fetchUser باغية تسنى الجواب ديال الـ API قبل ما تدير dispatch — مستحيل ترجع action وهي مازال ما جاتش.[1]

هنا كيدخل Redux Thunk: middleware ربطناه فـ src/index.js، وشغله وحد: كيinspect القيمة اللي كيرجع بها الـ action creator — إلا كانت function، كيناديها وحده ويدوز ليها dispatch كأول argument.[1] و الـ dispatch هادي هي نفس "الـ funnel" اللي كتلقى أي action وكتصاوبها لكل reducers فـ التطبيق.[1]

// src/actions/index.js — النتيجة النهائية بعد refactors
import axios from 'axios';
import { FETCH_USER } from './types';

export const fetchUser = () => async dispatch => {
  const res = await axios.get('/api/current_user');
  dispatch({ type: FETCH_USER, payload: res.data });
};

المسار: الـ نسخة الأولى جات بـ .then() (axios كيرجع promise، ومن بعد dispatch)، ومن بعد refactor لـ async/await (نفس منطق الدرس الفات — غير syntax أنظف).[4] و تفصيل مهم: الـ payload خاصو يكون res.data غير — حيت res كامل فيه config و headers و request، والوحيد اللي كيهمنا هو data اللي هو الـ user model.[5]

2 · fetchUser فـ App: نقطة الدخول

واش نناديوها من الـ header؟ هو اللي كيهتم بـ auth أصلا. ولكن حتى هكذا: الـ App component هو اللي غادي نمركزو فيه هاد اللوجيك — حيت قريبا غادي يزيدو أماكن خرين كيهتمو واش الـ user مسجّل (routes محمية مثلا)، والـ header ماشي غير هي.[2]

و باش نناديوها مرة وحدة أول ما التطبيق ي boot، خاصنا lifecycle method — علّاش نبدّلو الـ App من functional component لـ class component، ومن بعد نستعملو componentDidMount(): كتندعا أول ما الـ component يتعرض للشاشة.[2] علاش ماشي componentWillMount؟ جوج أسباب: (1) فـ إصدارات React الجاية ممكن يتندعا بزاف مرات، و convention كتعتبر componentDidMount المكان المفضل لكل initial Ajax request؛ (2) الفرق ديال التوقيت بيناتهم شبه معدوم.[2]

import { connect } from 'react-redux';
import * as actions from '../actions';

class App extends Component {
  componentDidMount() {
    this.props.fetchUser();
  }
  render() { /* routes... */ }
}

export default connect(null, actions)(App);

الربط: connect(null, actions) — الـ argument الأولى null حيت هاد الـ component ما محتاج والو من الـ state دابا، والثانية مجموعة الـ action creators (بالـ import * as actions كندوزو كاملين مرة وحدة).[3] ومن بعد تestنا: كيشوف الـ request كتمشي والـ action كتوصل للـ reducer.[3]

3 · auth reducer: ثلاث قيم + الـ header

هنا أدق جزء: واش نرجعو الـ payload مباشرة؟ المشكل: الطلب ممكن يتبدل ببطء (3G مثلا) — وإلا اعتبرنا بـ "ما مسجّلش" افتراضيا، الـ header غادي يورّي login button شوية، ومن بعد يتقلب فجأة لـ logout — وهادي هي الظاهرة اللي كنسميوها content jumping، وشكاية كثيرة ديال mobile web.[5]

الحل: ثلاث قيم واضحة كيرجع بها الـ authReducer:

  • null — الـ request مازال جاي، ما عرفنا والو (القيمة الافتراضية فبداية التطبيق).[5]
  • الـ user model — الـ request كمل والـ user مسجّل.[5]
  • false — الـ request كمل وما مسجّلش (السيرفر كيرجع string خاوي، وعلّاش نبدلوه لـ false بـ action.payload || false).[5]
// src/reducers/authReducer.js
export default function (state = null, action) {
  switch (action.type) {
    case FETCH_USER:
      return action.payload || false;
    default:
      return state;
  }
}

و فالـ header: connect + mapStateToProps اللي كتاخد الـ state كامل وترجع غير auth (كنستعملو destructuring: ({ auth }) => ({ auth })).[6] ومن بعد helper method سميتها renderContent(): switch على this.props.auth — null → والو (ما نورّيو حتى حاجة باش ما يتقفزش المحتوى)، false → زر Login With Google بـ href="/auth/google"، والـ default (object) → زر Logout.[7][6]

و باش تشوف الـ state null بعينك: شغّل network throttling فـ Chrome DevTools (Network tab → dropdown ديال الاتصال) — غادي تشوف نص ثانية "still deciding" قبل ما يقرّر.[7]

4 · redirects: login، logout، والـ logo

بعد login: كتمشي لـ OAuth flow وترجع لـ /auth/google/callback — ولكن كطلعت error! السبب: passport.authenticate middleware كتخدم و كتسالي، وماعندناش route handler من بعد، فـ Express كيقول "ما عندي ما ندير". الحل: نزيدو handler ثانٍ:[8]

// routes/auth.js
router.get(
  '/auth/google/callback',
  passport.authenticate('google'),
  (req, res) => res.redirect('/surveys')
);

بعد logout: جوج طرق ممكنين: Ajax request (أسرع، ولكن خاص action creator + reducer update + redirect يدويا) ولا anchor عادي بـ href="/api/logout" (full browser request — الأبسط بزاف، والكورس اختارها: ملي الـ user بغا يخرج، ما عادش عندنا معاه شغل).[9] والسيرفر تبدّل هو زادة: ما عادش كيرجع user model، بدل res.redirect('/') باش الـ user يرجع للـ landing.[9]

اللمسة الأخيرة: الـ Landing component خرج من dummy لـ components/Landing.js (functional component بـ h1 + نص ديال marketing + style={{ textAlign: 'center' }} — جوج curly braces: وحدة للـ JavaScript ووحدة للـ object).[10] و الـ logo فـ الـ header: الـ anchor كيصلح للـ external (بحال OAuth)، أما التصفح الداخلي فخاصو <Link> ديال React Router — و Destination ديالو كيتبدّل: to={this.props.auth ? '/surveys' : '/'} (مسجّل → dashboard، وإلا → landing).[11]

import { Link } from 'react-router-dom';

<Link to={this.props.auth ? '/surveys' : '/'} className="brand-logo">
  Emaily
</Link>

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو القيمة اللي كيرجع بها authReducer فـ حال "الطلب مازال جاي والجواب ماوصلش"؟

القيمة الافتراضية هي null = "ما عرفنا والو، الـ request مازال جاي" — وهاكذا ما كينيناش content jumping ملي يكون الـ network بطيء.[5]

2. علاش payload ديال FETCH_USER خاصو يكون res.data ماشي res كامل؟

res هو output كامل ديال axios (config, headers, request, status...) — والوحيد اللي كيهمنا الـ reducer هو data اللي هو user model نفسه.[5]

3. فـ renderContent()، ملّى this.props.auth بقات null، شنو خاصها يبان فالـ header؟

حالة null = مازال كنستناو الجواب — علّاش ما كنورّيو والو فهاد اللحظة، باش ما يتقفزش المحتوى مرة login مرة logout.[6][7]

4. مراجعة: من الدرس 9، علاش الـ BrowserRouter كيقبل غير child وحدة؟

قاعدة React Router: الـ BrowserRouter كيقبل child واحد فقط — علّاش كنلفّو جوج + الـ routes كاملين فـ div وحدة داخلو، وإلا الـ app كيطيح بـ error.[2]
