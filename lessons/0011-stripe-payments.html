الدفع بـ Stripe: tokens و charges و credits

الفلوس هي قلب أي freelance project: غادي نمشيو مع الـ flow كامل ديال الدفع — من زر "Add credits" حتى للـ credits اللي كتبان فـ header، والسيرفر ديالك عمرو ما كيشوف numbers ديال card.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقدر تشرح وتبني الـ payment flow كامل ديال أي تطبيق: Stripe Checkout كيعطيك token، السيرفر كيبدّلو بـ charge، ومن بعد كتزيد credits على الـ user وتحمي الـ route بـ middleware. هادي هي الخدمة اللي كتخلّي الـ client يدفع ليك.

1 · الـ flow كامل: من الزر حتى للـ credit

الكورس كيبدا من الـ UI: Payments component داخل الـ header، ملي الـ user يكون مسجّل، وكتبان ليه وصلة "Add credits". الكليك كيحل form ديال React Stripe Checkout اللي كتسجل الـ card.[1][2]

المهم بزاف: الـ form كتصاوب عند Stripe نفسها (iframe ديالهم)، وملي كتسالا، Stripe كترجع ليك token — يعني معرّف مؤقت ديال الـ card، ماشي numbers نفسها. السيرفر ديالك عمرو ما كيشوف numbers ديال card.[1]

بأي مثال الـ token بحال ورقة الأمانات فالمحطة: ملي كتحط الشنطة كيعطيوك ورقة صغيرة، والورقة بوحدها ما فيها حتى حاجة غالية. نتا كتصيفط غير الورقة للسيرفر، والسيرفر كيمشي بيها لـ Stripe باش يصاوب charge — الأرقام الحقيقية ديال card عمرو ما شافها.
نتيجة كتجي غلط باغي تصاوب form ديالك وتصيفط numbers ديال الـ card نيشان لـ API ديالك؟ غلط كبيرة: الـ numbers كتمشي فأي سيرفر خارج Stripe، ودخلتي فمسؤولية ديال PCI compliance كاملة. علّاش كاين token أصلا؟ باش Numbers تبقى غير عند Stripe — صيفط غير token.id لـ stripe.charges.create.

2 · الـ keys: publishable مقابل secret

عندك جوج مفاتيح: publishable key كتديها للـ client (كتبدا بـ pk_)، وsecret key اللي كتبقى غير عند السيرفر.[3] فـ Create React App، الـ env vars خاصهم يتبدلو بـ REACT_APP_ باش يقدرو يوصلو للـ client، وكتخزنيهم فـ config/keys.[3]

const stripe = require('stripe')(keys.stripeSecretKey);   // غير فـ server
// client: publishable key فقط — للـ Checkout form

الـ stripe npm module هو اللي كياخد الـ token وكيمشي بيه لـ Stripe API باش يصاوب الـ charge.[5]

publishable keypk_... كتمشي للـ client مع Checkout باش تبين form ديال Stripe. إلا تسربات، الخطورة محدودة حيت ما كتقدرش تسحب الفلوس بوحدها.
secret keyكتبقى غير فالسيرفر مع stripe.charges.create. إلا خرجات للـ client، أي واحد يقدر يصاوب charges باسمك.

3 · السيرفر: charge ثم credits

الـ route كيتسجل فـ ملف جديد billingRoutes (كيتصاوب كـ function كتاخد الـ app، ومن بعد كيتشعل من index.js) على POST /api/stripe.[4][5] باش توصل لـ req.body (فين كاين الـ token)، خاصك body-parser: npm install --save body-parser و app.use(bodyParser.json()).[6]

const charge = await stripe.charges.create({
  amount: 500,                       // 500 cents = $5
  currency: 'usd',
  description: '$5 for 5 credits',
  source: req.body.id                // الـ token
});

الـ charges.create كيرجع promise — نتا كتكتب async على الـ request handler و await قدام الـ call، ومن بعد كتوصّل لـ object ديال الـ charge (ID ديالو كيبدا بـ ch_، الـ currency، الـ amount...).[7]

من بعد، الـ user model عندو property جديدة: credits من نوع Number بـ default: 0 — يعني كلشي كيبدا بلا والو، وخاصو يخلّص باش يزيد. بعد ما الـ charge ينجح: req.user.credits += 5، ومن بعد await req.user.save() (بلا save، التبديل كيبقى غير فـ الذاكرة)، وفالأخير res.send(user) بـ النسخة الجديدة.[8]

علاش كترجعي الـ user نفسه للـ client؟ حيت نفس النمط اللي كيخدم مع الـ header: /api/current_user كيرجع الـ user كامل مع credits، وهكذا حتى الـ refresh كيبان فيه الرصيد صحيح.[10]

  1. Client → سيرفرنا POST /api/stripe و الـ token داخل JSON body
  2. body-parser → handler req.body ملّي بـ id ديال الـ token
  3. requireLogin → handler الـ user مسجّل؟ نادي next()
  4. سيرفرنا → Stripe stripe.charges.create بـ 500 cents
  5. Stripe → سيرفرنا charge object (ID كيبدا بـ ch_)
  6. handler → MongoDB credits += 5 ومن بعد save()
  7. سيرفرنا → Client res.send(user) — الـ header كيupdate الرصيد

4 · الحماية: requireLogin كـ route middleware

أول نسخة ديال الحماية كانت if (!req.user) return res.status(401)... داخل الـ handler — كتخدم، ولكن كتعاود من كل مرة. الحل: ملف جديد middleware/requireLogin.js كيصدّر arrow function بثلاث arguments: req, res, next.[9]

  • إلا ما كانش req.user (Passport هو اللي كيملأو): كترجع 401 وكتوقّف الـ chain — كتنادي next() غير إلا كلشي سالا مزيان.[9]
  • إلا كان مسجّل: كتنادي next() ويكمّل حتى لـ route handler.[9]
  • التركيب: app.post('/api/stripe', requireLogin, handler) — يعني كـ ثاني argument، وكتمرّره بلا ما تنادي عليه (Express كينادي بوحدو بحال callback).[9]

فالأخير، الـ header كيوري الـ credits من this.props.auth.credits فـ renderContent() ديال header.js، وملي كتجي الـ response الجديدة ديال /api/current_user، العدد كيتبدّل وحدو.[10]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. فهاد الـ flow، شكون اللي عمري ما كيشوف numbers ديال card؟

الـ form ديال Stripe هو اللي كيتعامل مع numbers، ويرجع token. السيرفر ديالنا كيتسلّم غير الـ token وكيبعثو لـ Stripe API.[1]

2. فين خاصك تحط requireLogin باش تحمي POST /api/stripe؟

الـ middleware ديال المشروع خاصو يطبق غير على routes مخصوصين، وكتمرّرو كـ argument للـ app.post بلا ما تنadiو عليه.[9]

3. مراجعة: من الدرس 1.1، React ملي كيحتاج data ديال surveys كيسول لـمن؟

Law #1: الـ React كيسول غير لـExpress API. حتى الـ POST ديال الـ token كيمشي بنفس الطريق — React → Express → Stripe.[4]

4. علاش خدامين body-parser قبل ما نوصلو لـ POST /api/stripe؟

بلا bodyParser.json()، req.body كيكون فارغ والـ token كيضيع — حيت الـ token جاي من JSON body ديال الـ POST.[6]
