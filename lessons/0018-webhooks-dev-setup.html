Webhooks: ngrok و encoding ديال survey data

ملي user كي clicki على link فـ email، الـ SendGrid باغية توصلنا بالخبرة — وهاد الدرس كيربط بيناتها وبين الـ Express server ديالنا فـdevelopment، وكيساوب الـ link اللي فيه survey id و choice.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقدر توقف webhook كامل فـlocal: tunnel بـngrok، SendGrid config، و link ديال email م encode بـsurvey id + choice — يعني أول vote كتوصل للسيرفر ديالك بلا ما تdeployi والو. هادي هي العملية اللي كتقلب "رسالة مبعوثة" لـ"data داخل الـ DB".

1 · webhook: سيرفر كيفاش كيهضر مع سيرفر

العلاقة ساهلة: webhook = سيرفر كيصيفط معطيات لسيرفر آخر حيت وقع شي حدث عندو. عندنا، الـ SendGrid كيسجل كل click فـemail ديالنا، ومن بعد كيصيفط لينا رسالة فيها شكون clicka و على شنو.[1]

نقطتين خاصك تعرفهم قبل ما نكتبو أي كود:

  • ماشي كل click = request. الـ SendGrid كيجمع الأحداث وكيصيفط bulk واحد كل شي كاع 30 ثانية ولا دقيقة — يعني الـ req.body ديالنا غادي يكون array ديال objects، ماشي event وحيد.[2]
  • فـproduction كلشي ساهل: الـ SendGrid غير كي POST على domain عام بحال email.com ولا your_app.herokuapp.com. أما فـdevelopment فالسيرفر ديالنا جالس على localhost:5000، وهو عنوان خاص بجهازنا وحدنا — الـ SendGrid عمرو ما غادي يوصل ليه.[2]

المشكلة هي كيفاش نوجدوا الـ public URL بلا ما نdeployi. الجواب: tunnel.

2 · ngrok: الـ tunnel ديال development

الكورس بدا بـLocalTunnel، ولكن الـ ملاحظة الرسمية كتقول بـهاد الخدمة ولات buggy ومشكلة، والبديل المعتمد هو Ngrok.[3] التسجيل و التنصيب:

# 1) account: https://dashboard.ngrok.com/signup
# 2) download: https://ngrok.com/download
ngrok config add-authtoken YOUR_AUTHTOKEN   # مرة وحدة
ngrok http 5000                             # كل ما تحل الـ dev

التفصيلة اللي كتقتل: كل ما تسد وتعاود تشغّل ngrok http 5000، الـ address تبدل — وخاصك ترجع تبدّلها فـSendGrid كل مرة.[3] غادي نشوفو فين بالضبط.

فالـ SendGrid dashboard: Settings → Mail Settings → Event Notification:

  • تفعّل Event Notification وحط فـHTTP POST URL: https://YOUR_TUNNEL_ADDRESS/api/surveys/webhooks — خاص يكون الـ route كامل، ماشي غير الـ domain.[4]
  • قبل كلشي، زيد route مؤقت فـExpress كي console.log(req.body) وكيرجع object خاوي باش ما نخلّيوش الـ request معلّق، ومن بعد ضغط Test Your Integration.[4]
  • من بعد دوز على clicked checkbox وفعّل الـ webhook كامل حتى تشوف Active — غير من بعد، أي email جديد هو اللي فيه tracking.[5]
  • الـ body اللي غادي يجي: array، كل عنصر عندو event (bounce, spam report, click…)، وحنا غير event: "click" اللي كيهمنا، وفيه email + url.[5]

وحدة أخيرة: الـ SendGrid ما كتقبلش جوج webhook URL (واحد للdev وواحد للproduction) — داكشي علاش فـdeploy خاصك ترجع تبدل الـ URL، ولا تدير account تاني.[5]

3 · encoding: فين كنخبعو survey id و choice؟

والي عندنا فـالـ event: نوع الـ click، الـ email، و الـ URL. المفقود: شكون survey؟ وشنو الجواب — yes ولا no؟ حتى واحد ما كيتكلم.[6]

الحل ماشي فـevent، الحل فـالـ link راسو. كانو users كيمشيو لـ/api/surveys/thanks ديما نفسو — بدّلناه فـtemplate ديال الـ email:

/api/surveys/<surveyId>/yes     # الزر الأيمن
/api/surveys/<surveyId>/no      # الزر الثاني

يعني كن encodeو الـ survey id و الـ choice داخل الرابط اللي الـ user كي clicki عليه، ونبقى على نفس الـ namespace ديال /surveys.[6] ملي الـ SendGrid يرجع لينا، الـ url فيها كامل المعلومات وحنا غير نقلبوها.

ملاحظة صغيرة: إلا clickiti على الزر، غادي توصل لـCannot GET حيت الـ route بعد ما تزادت — هادي غادي نصلحوها فالدرس الجاي ديال النتائج، ماشي دابا.[6]

4 · pre-processing: الـ pipeline قبل ما نمسسو الـ DB

الـ array اللي كتجي قذرة بzentwaً، وحنا خاصنا نصفّيوها قبل ما نهتمو بيها:[7]

  • duplicates: user كي clicki مرتين بجوج فثانية وحدة → جوج events متطابقين (email + url نيشان)، وخافنا race condition.
  • أخطاء ديال config: شي حد ممكن يزيد أحداث أخرى (bounce…) فـSendGrid → objects بلا url.
  • روابط برّا: click على terms of service ولا homepage → url ماشي ديال الـ survey.

الخطوات (كولشي كيمشي بـmap فوق req.body):[8]

  1. نخرجو pathname من الـ URL (دومين ما كيهمناش) بـnew URL(event.url).pathname.
  2. نجربو نستخرجو surveyId + choice بـpath-parser: p.test(pathname) مع pattern /api/surveys/:surveyId/:choice.
  3. نرجعو object فيه email, surveyId, choice — إلا ما لقاش match، الـ test كيرجع null وكن discardو الـ record.[9]
  4. نحيدو الـ undefined اللي خلا الـ map، ونحيدو الـ duplicates.
npm install --save lodash path-parser

الـ imports: الـ lodash بالـ convention ديال _، و URL جاي من Node نفسو (ماعندكش خاصو تنصبو). إلا شفتي TypeError: Path is not a constructor، الإصلاح هو const { Path } = require('path-parser');.[10][11]

Pitfall ما تديرش destructuring على نتيجة p.test() مباشرة (const { surveyId } = p.test(...)) — إلا رجع null غادي تقرا property من null ويطيح error. خلي match الأول وتأكد منها.[9]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. علاش خاصنا tunnel بحال ngrok فـdevelopment؟

localhost:5000 عنوان خاص بجهازك وحدك، والـ SendGrid كيحتاج domain عام باش يوصل — داكشي علاش كنصاوبو tunnel كيحول الطلب من public URL للسيرفر ديالنا.[2]

2. علاش خاص الـ link اللي فالـ email يحمل survey id و choice؟

الـ click event فيه غير email و url — والـ email وحده ما كيكفيش (نفس user ممكن يكون فجوج surveys). الترميز داخل الرابط هو اللي كيعطينا المعلومات.[6]

3. شنو كيدير p.test(pathname) إلا ما لقاش survey id و choice؟

الـ null هي الطريقة اللي كيخدم بيها الـ path-parser باش يقول "هاد الـ path ماشي ديالنا" — وحنا كنستعملوها باش نصفّيو الروابط اللي برّا الـ survey.[9]

4. مراجعة: فـ Law #1 ديال الكورس، شكون الوسيط الوحيد بين React و MongoDB؟

Law #1: الـ React عمرو ما كيتكلم مع MongoDB مباشرة — كلشي كيمشي React → Express API → MongoDB.[12]
