Emaily: الـ architecture و الـ user flow

التطبيق كامل فورقة واحدة — شكون كيتكلم مع شكون، وشنو كيوقع فكل step.

Compressed from course sections 01–02 · Print this page

التطبيق فجملة وحدة

Emaily = تطبيق ديال feedback collection. الـ product owner كيدخل بـ Google OAuth، كيشري credits، وكيصيفط surveys بالإيميل؛ الـ recipients كي clickaw على link ويخلّيو feedback؛ والنتائج كتبان فـ dashboard ديالو.[1]

الـ user flow

  1. الـ user كيسجّل ولا كيدخل بـ Google OAuth (بلا email + password).
  2. كييشري credits (Stripe) — الـ surveys كتصاوب credits باش تتصيفط.
  3. كييصاوب survey (title, subject, body, lista ديال recipients).
  4. الـ survey emails كيتمشيو للـ recipients.
  5. الـ recipient كيclicki على link فالإيميل ويخلّي feedback (yes/no).
  6. الـ feedback كيرجع من خلال Stripe webhook → كيتصاوب معالجة → كيتسجّل.
  7. الـ owner كيشوف النتائج فـ dashboard (الرصيد ديال credits + responses ديال surveys).[2]

الثلاث قوانين

  • الـ browser كيتلقى HTML document + JavaScript files فيها الـ React app من السيرفر ديالنا.[3]
  • الـ React عمرو ما كيتكلم مع MongoDB مباشرة — غير كيسول لـ Express API.[3]
  • الـ React "ما عندوش شنو يورّي" بلا data — كل screen كتبعّد بـ API response وحدة.[3]
