فـ production: Express كيقدم الـ React build

فـ development عندك CRA dev server قدام الـ Express — أما فـ production ما كاين حتى حاجة قدامو، بحال شي حد كيشغل الـ API ديالو وينسى الـ UI. غادي نربطهم فـ server واحد.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تعرف تشرح وتصحّح الـ deployment ديال أي React + Express app: علاش خاصك build step، فين كتدخل express.static و الـ catch-all route، وعلاش الـ refresh ديال /surveys فـ production كيرجع الـ page بدل 404. هادي هي النقطة اللي كتفرق بين "خدام على laptop" و "متعامل مع client".

1 · المشكلة: شكون كيقدم الـ HTML؟

فـ development، الـ Create React App كيخدم بـ dev server قدام الـ Express: هو اللي كيرجع الـ HTML والـ JS، والـ Express غير كيقدم الـ API. ولكن فـ production، ما كاين حتى سيرفر واحد: السيرفر ديالنا — وأول deployiyين فالكورس كانو كيقدرو غير الـ Express، الـ React app ما كانتش داخلة.[1]

developmentجوج سيرفرات: CRA dev server كيرجع HTML و JS، و Express غير كيجاوب على API.
productionسيرفر واحد: Express بوحدو كيرجع API والملفات ديال client/build وحتى index.html للـ catch-all.

يعني التحدي هو: كيفاش نفس الـ index.js يجاوب على جوج أنواع ديال requests؟

2 · جوج أسطر: static + catch-all

الكل كيتصاوب تحت if (process.env.NODE_ENV === 'production') — هادي هي الـ environment variable اللي كيضبطها Heroku (ولكلاً Platform) بوحدو، يعني هاد الكود ما كيتحمّلش فـ local.[2]

if (process.env.NODE_ENV === 'production') {
  // 1) أي ملف داخل client/build → رد بيه مباشرة
  app.use(express.static('client/build'));

  // 2) إلا ما فهمناش الـ route → index.html (React router غادي يتكفّل)
  const path = require('path');
  app.get('*', (req, res) => {
    res.sendFile(path.resolve(__dirname, 'client', 'build', 'index.html'));
  });
}
  • الأول كيجيب الملفات المحددة (مثلاً client/build/static/js/main.js).[2]
  • الثاني هو الـ catch-all: إلا ما لقاش حتى route handler وما لقاش حتى ملف، كيعطيك index.html وكيخلّي React router هو اللي يفهم الـ path.[2]
  • الترتيب هو القانون: Express كيبدا من الفوق — API routes → الملفات ديال client/build → فالأخير الـ catch-all.[2]
بأي مثال الـ catch-all بحال موظف الاستقبال اللي كيبقى فالأخير: إلا حتى واحد ما عرف الملف المطلوب ولا الـ route ديال API، هو كيعطي index.html وكيخلي React Router هو اللي يفهم شنو يبين.
نتيجة كتجي غلط دفعتي الـ app وكتعمل refresh على /surveys فـ production وكتشوف 404 Cannot GET: السيرفر ما لقاش ملف اسمو build/surveys وما عندوش catch-all. الحل: بعد express.static زيد app.get('*', ...) اللي كيرجع index.html، وحطّها فالأخير من بعد الـ API routes.

3 · الـ build step والـ deploy

الـ client/build ماشي موجود بالسحر: كيتصاوب بـ npm run build من داخل مجلد client، وكيخلي bundle واحد ديال JS + CSS. كل تبديل فـ src خاصو يتبعو build جديد قبل ما تدفع.[3]

المسار ديال الـ deploy اللي اختارو فالكورس: commit → push → الـ platform كتنصب الـ dependencies ديال السيرفر → من بعد كتصاوب client build (اختارو "option number two" اللي كتزيد الـ build step فالـ deploy نفسها).[4]

  1. commit و pushالتبدالات ديال src كتمشي لـ GitHub.
  2. تنصيب deps ديال السيرفرالـ platform كنصب الـ dependencies ديال الجذر أول حاجة.
  3. build ديال الـ clientheroku-postbuild كيدخل لـ client، كنصب deps ديالو، ومن بعد npm run build كيصاوب client/build.
  4. start ديال الـ serverExpress كيبدا وكيقدم الـ API والـ static والـ catch-all كلشي من سيرفر واحد.
"heroku-postbuild": "NPM_CONFIG_PRODUCTION=false npm install --prefix client && npm run build --prefix client"

فـ Render (البديل اللي كيتحط فـ ملاحظات الكورس)، كتبدّل الـ Build Command من npm install إلى npm install && npm run heroku-postbuild — نفس الفكرة: الـ server deps قبل، الـ client build من بعد.[5]

وإلا طاح الـ build بـ أخطاء ديال versions (مثلاً SyntaxError: Unexpected token من @hapi): المشكل هو Node version mismatch بين جوج machines — الحل: حيّد package-lock.json (client + server)، استعمل LTS version ديال Node، وطابق engines فـ package.json.[6]

4 · الاختبار: علاش refresh كيخدم

ملي كتكتب /surveys فـ address bar، هادي هي full page reload — request جديدة كتمشي للسيرفر بلا ما يمشي معك شي حاجة من الـ SPA. السيرفر ما لقاش ملف اسمو build/surveys، وفالأخير كيرجع index.html document، الـ body كيحمّل الـ React app، ومن بعد client-side router هو اللي كيتسلّم الـ route.[7]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو كيدير app.use(express.static('client/build'))؟

هادي هي الـ static middleware: إلا كان شي ملف كيطابق الـ request داخل client/build، كيرجعو مباشرة — كتعطي الملفات قبل ما توصل للـ catch-all.[2]

2. شنو كيوقع ملي الـ user يكتب /surveys فـ address bar فـ production؟

هادي هي full page reload: ما كاين حتى route handler لـ /surveys وما كاينش ملف بنفس الاسم، وفالأخير الـ catch-all كيرجع index.html وكيسلّم الـ routing للـ React.[7]

3. علاش خاص npm run build قبل ما ندفعو لـ production؟

السيرفر ما كيعرفش يقرا src/*.jsx — هو كيقدم غير الـ ملفات الجاهزة من client/build، وملف جديد فكل مرة تبدل src.[3]

4. مراجعة: من درس Stripe، فين كيتسجل number ديال credits ملي الـ charge ينجح؟

الـ user model عندو credits بـ default: 0، ومن بعد الـ handler كيزيد 5 وكيدير await save() — يعني الـ DB هي source of truth ديال الرصيد.[8]
