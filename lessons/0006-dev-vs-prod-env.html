Dev vs Prod: keys و environment variables

الـ OAuth خدام محليا وحان وقت الـ deploy: جوج sets ديال keys، resources منفصلة، و environment variables اللي كيخلي الكود يعرف شكون هو.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقدر تحط أي app ديالك فـ production بلا خوف: set ديال keys خاص بالـ dev، database و Google project منفصلين، و environment variables فوق Heroku/Render — وحتى اللابتوب ديالك ملي يتسرق، credentials ديال users كيبقاو بعيدة عليه.

1 · جوج sets ديال keys، ماشي وحدة

فـ config/keys.js ديالنا كامل الـ API keys: Google client ID و secret، المفتاح ديال cookies، و MongoDB URI — وهو الملف اللي كيتصاوب منو الـ require('./config/keys') فكل بلايص. المشكل: دابا عندنا set وحدة فقط ديال هاد الـ keys، والكورس كيقول بلي هادا غادي يجيب لينا مشاكل.[1]

الحل: جوج sets منفصلين — set ديال development للّابتوب ديالك (Mongo ديالك، Google API ديالك، cookies ديالك)، و set آخر تماما ديال production اللي هو الـ deployment ديالنا فوق Heroku.[1] علاش؟ جوج أسباب:

  • الأمان: الـ production keys كيتسجلو بعيدا على خوادم Heroku، والـ dev keys كيبقاو غير على اللابتوب. اللابتوب ممكن يتسرق، وفوقو ملف نصّي فيه كامل الـ keys — اللي كيولّيه القدرة على MongoDB ديالك و Google API و cookies ديال users. بصح credentials ديال dev، نمسحوها ونبدلوها؛ أما credentials ديال production فمتبقاوش فراس اللابتوب.[1]
  • جوج databases: الـ production database خاصها تكون نظيفة فيها غير data ديال users وكيتتعامل بيها بحذر دائم. أما dev فنقدرو نزيدو records ونمسحو collections ونبدلو كلشي بلا خوف نكسرو شي production data.[1]

2 · resources منفصلة من البداية

التقسيم ماشي غير ديال الكود: خاصك resources حقيقيين منفصلين. فـ MongoDB Atlas نصاوبو database جديد (سميناه emaily-prod، والديال dev هو emaily-dev اللي كيبان فـ dashboard ديالك) مع database user جديد بـ credentials مختلفة على ديال dev.[2]

وفـ Google Developer Console، نصاوبو project جديد emaily-prod باش نعزلو الـ credentials: نفس الـ Google Console كيتسجل فيه الـ OAuth ديال dev والـ ديال production، والفصل كيضمن بلي ملي تبدل شي حاجة فـ dev، الـ production ما تتحركلش.[2] ملاحظة عملية: الـ project الجديد ما كيتصاوبش فوري — خاصك تستنا حتى يكمل الـ creation، وإلا ممكن تلقى راسك كتعدّل على emaily-dev بالغلط.[2]

وأول ما توصل لـ OAuth credentials ديال production: authorized JavaScript origin و authorized redirect URI خاصهم يكونو domain ديال production ماشي localhost:5000. باش تلقى العنوان ديالك: شغّل heroku open من terminal وخذ العنوان من address bar، ومن بعد زيد عليه /auth/google/callback للـ redirect URI.[3]

3 · NODE_ENV: كيفاش الكود كيختار

دابا keys.js ما عادش كيخزّع raw keys — كيولّى كيقرر شكون هو. الـ variable process.env.NODE_ENV هي اللي كتجاوب: فوق Heroku كيتصاوب تلقائيا للسلسلة 'production'، أما فوق اللابتوب فما كت يكونش 'production'، وهكذا الكود كيرجع ليك الملف الصحيح.[4]

// config/keys.js — logic فقط، بلا raw keys
if (process.env.NODE_ENV === 'production') {
  module.exports = require('./prod');   // قيم من process.env
} else {
  module.exports = require('./dev');    // قيم حقيقية، ما كتتمشّنش
}

أما prod.js كيexport نفس property names بالضبط (باش أي ملف ديال المشروع يقدر يستعملهم بلا تغيير)، ولكن القيم كيجيو من environment variables.[4] والـ convention: environment variables بالحروف الكبيرة والتشرطة السفلية — GOOGLE_CLIENT_ID، GOOGLE_CLIENT_SECRET، MONGO_URI، COOKIE_KEY.[4]

وأخيرا تقسيم الـ git: dev.js كيتضاف لـ .gitignore (ما كيتصدّش)، أما keys.js و prod.js كيت-commitو — وإلا ما commitinash prod.js، الـ Heroku server غادي يقلب على الملف ملي يخدم و ما يلقاش ويرمي error ضخم.[4]

كيت-commit للـ repo keys.js + prod.js — غير logic و قيم جايين من process.env، حتى مفتاح واحد ما كاين فهاد الملفين.[4]
ما كيتصدّش أبدا dev.js — فيه raw keys حقيقية ديال dev، وزيدو فـ .gitignore باش ما يوصلش لـ repo.

4 · environment variables فوق المنصة + قاعدة الـ HTTPS

فين كيتصايبو القيم ديال process.env؟ فوق المنصة ديال deployment. فـ Heroku: dashboard ديال الـ app → tab ديال Settings → config variables (key/value pairs).[5] وفـ Render (بديل Heroku بلا free tier): sidebar → Environment → زر Add Environment Variable، وتزيد pair pair: COOKIE_KEY (أي string عشوائي)، GOOGLE_CLIENT_ID و GOOGLE_CLIENT_SECRET من Google Project Dashboard → APIs and Services → Credentials → OAuth 2.0 Client ID، و MONGO_URI.[6]

وآخر مصيبة كتجي بعد الـ deploy: redirect_uri mismatch. Google كيشوف http://...herokuapp.com بينما نحنا سجلنا https://... فـ authorized redirect URI — يعني شي حاجة كترجّع الـ flow لـ HTTP بدل HTTPS.[7] القاعدة اللي خاصك تحطها فراسك: كلشي مربوط بـ auth خاصو يكون HTTPS حيت كيتصرف مع بيانات حساسة.[7]

نتيجة كتجي غلط من بعد الـ deploy، Google كيرمي ليك صفحة redirect_uri mismatch — حيت الـ request رجع بـ http:// بينما Authorized redirect URI مسجل بـ https://. الحل: حل Google Console وتأكد بلي الـ redirect URI هو نفس domain بالضبط اللي خذتيه من heroku open، بـ https وكامل /auth/google/callback.[7]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. علاش خاصك جوج sets ديال keys (dev + production) ماشي set وحدة؟

الـ production keys كيتسجلو بعيدا على خوادم Heroku والـ dev keys كيبقاو غير على اللابتوب — وهكذا حتى لو تسرق اللابتوب وشاف الملف، credentials ديال الـ users ما توصلش ليه.[1]

2. فوق Atlas و Google Console، شنو خاصك تدير قبل ما تدير الـ deploy ديال production؟

التقسيم كيضمن بلي نقدرو نكسّرو الـ dev ميت مرات بلا ما نأثرو على production data: database جديد emaily-prod بـ credentials جديدة، و Google project جديد emaily-prod.[2]

3. كيفاش الكود ديالنا كيعرف واش راه خدام فـ production؟

فوق Heroku الـ NODE_ENV كيتصاوب تلقائيا للسلسلة 'production'، وkeys.js كيدير branch على هاد الشرط باش يرجع prod.js ولا dev.js.[4]

4. مراجعة: من الدرس 1.1، ملي الـ React بغا data ديال الـ surveys، مع شكون كيتكلم؟

Law #1: الـ React عمرو ما كيتكلم مع MongoDB مباشرة — كلشي كيمشي React → Express API → MongoDB. وحتى فـ production، نفس الطريق كتبقى هي نفسها.
