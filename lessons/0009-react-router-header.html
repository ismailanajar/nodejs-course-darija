دابا خاصو للـ app وجه: routes بـ exact، Header كيبان فكل بلاصة بـ Materialize، وخطة fetchUser باش نعرفو واش الـ user مسجّل.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقدر تسيّر أي تصفح فـ React app: BrowserRouter + Route مع exact باش ما يتراكبوش الـ components، Header كيبان دائما بـ Materialize عبر Webpack import، و الخطة الكاملة ديال GET /api/current_user.

1 · React Router: الأدوات والقواعد

كل Route هو زاوج بين rule — عنوان اللي ممكن يزورو الـ user والـ components اللي خاصهم يبانو فالشاشة. وكلشي كنكتبوه فـ App.js، حيت هي مسؤولة على الـ view layer، أما index.js فكيبقى Redux setup.[1]

الـ import جاي من react-router-dom: كاينة ثلاث مكتبات (dom، native، core) — غير الـ dom هي اللي كيهمنا فهاد النوع ديال التطبيقات.[1] وجوج أدوات:

  • BrowserRouter — "الدماغ" ديال React Router: كيقرا الـ URL الحالي وكيبدّل الـ components اللي ظاهرين.[1]
  • Route — الـ rule نفسها: path + component.[1]

جوج قواعد خارجية قبل ما نكتب: (1) الـ BrowserRouter كيقبل child واحد فقط — جوج div كيعطيك error، علّاش كنلفّو الـ routes كاملين فـ div وحدة.[2] (2) الـ path="/" كيعني الـ root route ديال التطبيق — عمرو ماكتبو الـ domain (ماشي emaily.com ولا herokuapp.com، غير مسار الـ URL).[2]

import { BrowserRouter, Route } from 'react-router-dom';

<div className="container">
  <BrowserRouter>
    <div>
      <Header />
      <Route exact path="/" component={Landing} />
      <Route exact path="/surveys" component={Dashboard} />
      <Route exact path="/surveys/new" component={SurveyNew} />
    </div>
  </BrowserRouter>
</div>

2 · قاعدة exact والـ components الدائمين

إلا مشيتي لـ /surveys ونتفاجأ: كتشوف landing + dashboard مع بعضياتهم! السبب: الـ route ديال / كيقبل بـ greedy matching — السلسلة / موجودة داخل /surveys، فـ React Router كيقول موجود ويرسم الـ Landing.[3] الحل: prop ديال exact (= exact={true}) اللي كيقول "خاص المسار يطابق بالضبط".[3]

بأي مثال تخيل حارس كيسول غير واش السمية كتبدا بنفس الحرف: أي واحد عندو نفس البداية كيدخلو. هكذا داير Route path="/" بلا exact — أي path كيبدا بـ / كيقبلو. exact كتقول للحارس يقارن العنوان كامل حرف بحرف.

نفس المشكل كيتكرر مع /surveys/new: كيتطابق مع /surveys (موجودة فـ البداية)، فكيتبان الـ dashboard مع الـ SurveyNew — وهادا ماشي اللي بغينا، يعني الـ dashboard زادة خاصها exact.[4]

بلا exact<Route path="/" /> كيقول "أي مسار كيبدا بـ / كافي" — علّاش كيشوف /surveys وكيشعل الـ Landing زادة مع الـ Dashboard.
بـ exact<Route exact path="/" /> كيقول "غير / بوحدها" — وكل مسار كيرسم غير الـ component ديالو وحده.

و بخصوص الـ Header: ماشي هو الطريق — كنحطو component عادي فوق الـ routes كاملين فـ نفس الـ div اللي داخل BrowserRouter، وهكذا كيبان دائما فكل صفحة، ومحتواه هو اللي غادي يتبدّل من بعد حسب auth.[4]

Headerكيبان دائما فكل صفحة، غير المحتوى ديالو اللي كيتبدل حسب auth
Route contentالجزء اللي كيتبدل: Landing ولا Dashboard ولا SurveyNew حسب path
BrowserRouterالدماغ اللي كيقرا URL الحالي وكيختار شكون يبان

3 · Materialize: من link tag حتى Webpack import

الـ Header خرج لملف خاص components/header.js كـ class component، ومن بعد درنا install ديال Materialize CSS كـ npm module من داخل client/ (ماشي بـ link tag و CDN).[5]

كيفاش كنوصلو للـ CSS ديال module؟ Webpack — اللي جا معا create-react-app كـ module loader: كيجمع ملفات وحدة وحدة لخرج ملفات output، وكيعرف حتى يتعامل مع CSS: ملي كتشوف import ديال ملف CSS، كيتعامل معاه CSS ماشي JavaScript.[6]

// src/index.js — فـ أعلى الملف
import 'materialize-css/dist/css/materialize.min.css';

ثلاث تفاصيل: خاص extension (.css ماشي كيف الـ JS اللي كيتخمّم)، بلا relative path (webpack كيفهم بلي كنعنيو npm module من node_modules)، و ما تحتاجش variable — الـ import بوحدو كافٍ، وخاص restart ديال الـ server.[6]

الـ markup ديال الـ navbar جا من docs ديال Materialize (navbar component): nav فيه div.nav-wrapper، وداخلو anchor بـ left brand-logo (السمية ديال التطبيق)، وإلى جنبها ul.right فيها li ديال زر الـ login.[7] وفـ React: className ماشي class.[7]

و ملاحظة خفية بزاف: Materialize كتوقع بلي عندك root element بـ class container — علّاش كنزيدوه للـ top div ديال App.js، وإلا الـ navbar كيلزق على حافة الشاشة.[8]

نتيجة كتجي غلط الـ navbar كيلزق على حافة الشاشة بلا أي هامش، والـ links مرصوصين مع بعضياتهم. علّاش؟ نسيتي class ديال container. الحل: زيد className="container" على الـ top div ديال App.js باش Materialize يعطيك المقياس ديالو.

4 · current user API: الخطة ديال fetchUser

الـ header دابا فيه مشاكل تلاتة: الـ logo ماشي clickable، زر الـ login كيبدا وما كيدير والو، والمحتوى ما عادش يتبدل حسب auth.[8] والحل كيبدا من عند السيرفر: عندنا route جاهز GET /api/current_user اللي كيجاوب واش الـ user مسجّل.[9]

الخطة كاملة (غادي نبنيوها فالدرس الجاي خطوة بخطوة): App component — اللي هو الـ route component — كينادي action creator fetchUser أول ما يboot؛ داخلها axios كتصاوب Ajax request لـ /api/current_user؛ ومن بعد Redux Thunk كيسيّر الـ dispatch ديال الـ action للم reducer كاملين؛ الـ authReducer كيحدث state؛ ومن بعد الـ header كيتصل بالـ store ويتبدّل محتواه.[9]

و عمليا، غادي نحتاجو: نثبتو axios و redux-thunk من داخل client/، ونزيدو proxy rule ثانية باش /api/* (و /auth/google) يتوجهو للـ Express على localhost:5000.[9]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. ملّى مشيتي لـ /surveys وشفتي landing + dashboard مع بعضياتهم، شنو السبب؟

الـ route ديال / كيقبل الطابق الـ greedy: السلسلة / موجودة داخل /surveys، فـ React Router كيعتقد بلي الـ Landing خاصها تبان — والحل هو exact.[3]

2. شنو المهمة ديال الـ prop exact؟

exact كيحمّل المسار يطابق بالضبط — بلا منه، /surveys كتقبل منطاق / و /surveys/new، ونتا كتشوف components ما طلبتيهمش.[4]

3. علاش حطينا className="container" فوق الـ top div ديال App؟

Materialize كتوقع بلي عندك root element فيه container — بلاه الـ navbar كيلزق على حافة الشاشة والتخطيط ما كيتضمنش.[8]

4. مراجعة: من الدرس 8، الـ key اللي تعطيه لـ combineReducers({ auth: ... }) فين كيسكن فالنتيجة؟

القاعدة: keys ديال combineReducers = keys ديال state object — يعني القيمة اللي كيصنعها authReducer كتجي فـ state.auth، وهادي هي اللي غادي يشدّها الـ header بـ mapStateToProps.
