Redux و auth reducer: أول state ديالنا

الـ client واجد ودابا خاصو memory: نصاوبو Redux store، نربطو الـ Provider، ونخرّجو أول reducer حقيقي — authReducer اللي كيقرر واش الـ user مسجّل.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تقدر تربط Redux من الصفر فـ React app: index.js = store + Provider، reducers/index.js = combineReducers، و authReducer اللي كيحفظ حالة تسجيل الدخول — وهي أول slice ديال state فهاد المشروع كامل.

1 · قبل Redux: refactoring و تهيئة الـ client

القسم بدا صغيرة: async/await — syntax ديال 2017 باش نكتبو asynchronous code بشكل أنظف من الـ callbacks.[1] وأول استعمال عندنا كان تصفيات الـ promises ديال Google strategy callback فـ services/passport.js (البحث على user، وإلا ما لقيناش نصاوبوه) من callbacks لـ await.[2]

من بعد تصوّرنا: diagram فيه green boxes = backend و blue boxes = frontend — الـ server setup والأوثرنتيكشن خلاص تهدات، ودابا pivot كامل للـ client setup: React، React Router، Redux، و هدف وحدو: نعرفو واش الـ user authenticated أصلا. نصيحة ديال الكورس: خدّم فجيهة وحدة (backend ولا frontend) فنفس الوقت — وإلا كتجمع بيناتهم، الطريق المباشرة للمشروع spaghetti code.[3]

التهيئة العملية: صافينا كامل boilerplate اللي صاوبو لنا create-react-app فـ src — ولكن ما نمسحوش registerServiceWorker.js، و كذالك setupProxy.js ما تمحاش (اللي صاوبناه فالدرس الفات).[4][5]

src/
  index.js          # CRA كيعيّنو كـ root file (منعرّفش تبدلو) — Redux/data setup
  reducers/         # غادي نصاوبوه دابا
  components/
    App.js          # component = حرف كبير — view layer / router
  registerServiceWorker.js   # ما تمحاش
  setupProxy.js              # ما تمحاش

و من بعد خلقنا components/App.js — حرف A كبير حيت كيexport component، أما الملفات اللي كيخرجولك غير functions فحرف صغير (بحال index.js).[4]

2 · Redux store + Provider فـ index.js

التقسيم عندنا واضح: src/index.js = Redux setup (الداتا)، و App.js = React Router setup (الـ view layer).[6] وثبّتنا react-redux — هي المكتبة اللي كتخلي Redux والـ React يخدمو مع بعضياتهم.[6]

الخطة ديال الـ state عندنا: reducers جوج — واحد auth (واش الـ user مسجّل؟) و واحد surveys (ليست ديال surveys اللي صاوبهم) — الـ surveys غادي يجي من بعد، ملي نكملو الـ backend ديالهم.[6]

مراجعة سريعة ديال الـ flow: component كينادي action creator → كيرجع action → الـ action كيتصاوب لكل reducers → combineReducers كيحدث state فـ store → الـ state الجديد كيرجع للـ components وكيسبّب re-render.[6]

Component → dispatch(action) → reducer → store: state جديد → re-render
رجوع للـ Component بالمحتوى الجديد — ومن بعد كيتكرر نفس الدوران مع أول action جاي

و التطبيق فـ index.js: صاوب الـ store، ومن بعد حط <Provider> — component جا من react-redux، وهو الـ "glue" اللي بين الجيهتين: كيلبّس App وكيدوز ليه الـ store.[6]

<Provider store={store}>
  <App />
</Provider>

3 · auth reducer + combineReducers

نصاوبو src/reducers/ وفيها جوج ملفات:[7]

  • authReducer.js — حرف a صغير حيت الملف كيexport function ماشي component.[7]
  • index.js — التسمية convention: باش import reducers from './reducers' يلقى الملف index.js اللي داخل المجلد تلقائيا.[7]

الـ reducer نفسو: function كتاخد state و action، وكتسوّي switch على action.type — دابا ما كايناش types، غير الـ default case اللي كيرجّع state بلا تبديل. وحنا الـ state كيبدا undefined، خاصك تعطيه initial value — الكورس بدا بـ object خاوي (وقال بلي غالبا غادي يتبدل من بعد).[7]

// src/reducers/authReducer.js
export default function (state = {}, action) {
  switch (action.type) {
    // case FETCH_USER: ...
    default:
      return state;
  }
}

// src/reducers/index.js
import { combineReducers } from 'redux';
import authReducer from './authReducer';

export default combineReducers({ auth: authReducer });

القاعدة الذهبية هنا: الـ keys اللي تعطيهم لـ combineReducers هما الـ keys اللي غادي يخرجو فـ state object — علّاش سميناه auth حيت state.auth هو اللي غادي يكون.[8] وآخر خطوة: import reducers from './reducers' فـ src/index.js وعطيهم كأول argument ديال createStore.[8]

نتيجة كتجي غلط كتقرا state.auth وتلقّى undefined والـ header كيبقى خاوي — حيت الـ state كيبدا خاوي قبل ما أي action يوصل، وإلا ما عطيتيش initial value، الـ reducer كيرجّع undefined فـ هاد الـ case. الحل: أعطي القيمة الافتراضية فالتوقيع function (state = {}, action)، ومن بعد تبديلها ملي تجي types حقيقية.[7]

4 · علاش auth state مهم

واش مستاهل نهدرو على reducer صغير بحال هادا؟ الجواب: حيت أول حاجة كتبان للuser هي الـ header، ومحتواه كيتبدّل حسب الـ auth: ملي ما مسجّلش — زر sign in with Google؛ ملي مسجّل — كيتحيد ويبان بدلو logout و أزرار الـ credits.[9]

و زيادة على الـ header: الـ routes كيتصرفو بشكل مختلف. الـ header كيبان دائما فكل بلاصة؛ الـ landing page (التسويقية) خاصها تشاف بلا تسجيل — عادي؛ أما الـ dashboard (ليست ديال surveys) و /surveys/new (الـ form) ف خاصهم login وماشي غير نقاش.[9]

هادي هي خطة الدروس الجاية: نصاوبو الـ components، نربطوهم بـ React Router، ومن بعد نجيبو الـ data ديال الـ user للـ client.[9]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. شنو المهمة ديال الـ authReducer؟

الـ auth reducer مسؤول غير على سؤال واحد: واش الـ user حاليا logged in؟ — والقيم اللي كيرجع منهم غادي تستعملها الـ header والـ routes باش يقررو شنو يورّيو.[9]

2. مراجعة: من الدرس 1.1، ملي الـ React بغا data ديال الـ surveys، مع شكون كيتكلم؟

Law #1: الـ React عمرو ما كيتكلم مع MongoDB مباشرة — React → Express API → MongoDB. وحتى الـ auth state اللي دابا نبنيو، غادي يجي من نفس الطريق عبر API call.

3. فـ combineReducers({ auth: authReducer })، شنو كيعني الـ key auth؟

القاعدة: الـ keys اللي تعطيهم لـ combineReducers هما بالضبط الـ keys اللي غادي يتسجلو فـ state object — يعني غادي تلاقي القيمة ديال هاد الـ reducer فـ state.auth.[8]

4. علاش الـ header كيحتاج auth state ديال Redux؟

محتوى الـ header كيتبدّل: sign in with Google ملي الـ user ما مسجّلش، و logout + أزرار credits ملي يكون مسجّل — وهاد التبديل كيتبنى على نفس الـ state اللي كيصنعو authReducer.[9]
