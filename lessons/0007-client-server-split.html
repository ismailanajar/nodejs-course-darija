الـ Client: separate server و CRA proxy

دابا عندنا Express و MongoDB، وحان وقت الـ React: نصاوبو client/ بوحدها، نشغلو جوج خوادم بأمر واحد، ونحلو مشكل الـ relative links بـ proxy.

~12 دقايق · Quiz ديال retrieval فالأخر

Win ديال هاد الدرس غادي تعرف تفصل الـ client على الـ server فنفس المشروع: client/ جوه dir ديال السيرفر بـ package.json خاصو، أمر واحد (npm run dev) كيشغّل جوج، و proxy اللي كيحوّل الـ API requests للسيرفر الصحيح — ف dev، و كيفاش كيتبدّل الوضع فـ production.

1 · الفصل: client/ جوه dir ديال السيرفر

الـ create-react-app صاوب لينا مجلد جديد اسمو client/ داخل dir ديال المشروع، وهو اللي كيسكن فيه كامل الـ React side ديال التطبيق.[1] المهم تعرف: الـ React project عندو server خاص بيه — كيتفتح بـ npm start من داخل client/، وكيرفع التطبيق على localhost:3000.[1]

هادي هي النقطة اللي كتقلب كلشي: من دابا عندنا جوج servers فـ development — الـ React server (اللي كي bundle الـ components بـ Webpack و Babel ويخرج ملف bundle.js للـ browser)، و الـ Express server (اللي كيخرج غير JSON و data).[1] علاش نستحملو جوج؟ حيت Create React App هو أحسن طريق باش نبداو: كامل الـ config ديال Webpack و Babel و loaders كيجي مصاوب من التّلا، وتوفير هادا يستاهل الـ extra setup ديال الفصل.[1]

Browserكيرجّع domain اللي راه فيه — localhost:3000 — على كل relative link[4]
React serverlocalhost:3000 — CRA، Webpack، Babel، و الـ proxy اللي كيحوّل الـ requests اللي ما عرفش
Expresslocalhost:5000 — /api و /auth/google
MongoDBالـ data ديال users والـ surveys

وإلا كنتي كتمشي بالطريقة الساهلة: عندك zip ديال starter boilerplate — نزّلو و extraiه فـ dir ديال السيرفر الموجود، والنتيجة خاصها تكون:

server/
  client/

cd client
npm install

و ملي تكمّل، ماعنكش خاطر تزيد dependencies ديال client من بعد — الـ boilerplate قدّامك.[2]

2 · جوج terminals ولا script وحدة

باش تخلّص الـ client والـ server مع بعضياتهم: الطريقة القاسية = terminal ثانية داخل client/ بـ npm start وterminal الأولى داخل السيرفر بـ npm run dev — خدامة، ولكن باغيين أحسن.[3]

الطريقة الساهلة = package ديال concurrently كيشغّل جوج بأمر واحد. وقبل من نزيدو، لاحظ ميزة كبيرة: دابا عندنا package.json جوج — واحد فالـ server (فيه deps ديال backend) و واحدداخل client/ (فيه deps ديال React) — وخاصك تعرف دايما فين راك كتكتب.[3]

npm install --save concurrently   # من داخل dir ديال السيرفر

"client": "npm run start --prefix client",
"server": "npm run server",        # الـ script القديم ديال dev تبدّل
"dev":   "concurrently \"npm run server\" \"npm run client\""

npm run dev                        # جوج فنفس terminal

الـ --prefix client كيقول له "مشي داخل client/ ودير npm run start من تما"، و الـ backslashes غير باش ن escape الـ double quotes اللي خاصها تكون محيطة بالـ script فـ JSON.[3]

3 · الـ stumbling block ديال relative links

السيرفر خدامين مع بعضياتهم — حتى مشاو للـ OAuth. الـ مشكل: أي relative link (بحال /auth/google) الـ browser كي prepend عليه domain اللي راه فيه دابا، وهو localhost:3000 (الـ React server) — ماشي localhost:5000 (الـ Express).[4] والنتيجة: Google كيشوف بلي باغيين نرجّعو الـ user لـ localhost:3000/auth/google/callback وهو ما مسجلش عندو — redirect_uri mismatch.[4]

الحل ديال الكورس هو proxy: قاعدة كتقول للـ React server "أي طلب ما عرفتوش، حوّلو للـ backend على localhost:5000" — وهكذا /auth/google كتوصل للـ Express وكيمشي معاه الطريق الصحيح.[5]

browserlocalhost:3000
→
React dev serverغير ما تعرفش → proxy
→
Expresslocalhost:5000

و زيادة على ذلك: خاصك تزيد redirect URI ديال dev — http://localhost:3000/auth/google/callback — فـ authorized redirect URIs ديال Google console. الكورس كيأكّد: غير فـ development بغيتي نرتاحو شوية، أما الإعداد ديال production كيبقى super secure وما يتبدلش.[5]

4 · CRA تبدّل: setupProxy.js

الفيديوهات كيتكلمو على proxy field داخل package.json ديال الـ client، ولكن CRA تبدّل الطريقة ومن بعد هاد الخطوة: دابا خاصك هاكا:[6]

# 1) من داخل client/
npm install http-proxy-middleware@2

// 2) client/src/setupProxy.js — CRA كيقلّدو بالأسماء بلا ما ن importiوه
const { createProxyMiddleware } = require("http-proxy-middleware");
module.exports = function (app) {
  app.use(
    ["/api", "/auth/google"],
    createProxyMiddleware({ target: "http://localhost:5000" })
  );
};

# 3) npm run dev من جديد (أي تعديل على setupProxy.js كيجبّر restart)

تنبيهات ديال الفرق: ما تحطش الـ proxy config فـ package.json (غادي يرمي ليك "proxy" in package.json must be a string)، وما تزيدش changeOrigin: true (غادي يكسّر الـ redirects كاملين).[6]

نتيجة كتجي غلط شعلت الـ app ولقّيت الـ error "proxy" in package.json must be a string — يعني حطيتي proxy field داخل package.json ديال الـ client. الحل: حيدو من تما، وثبّت http-proxy-middleware@2 وحط القاعدة فـ client/src/setupProxy.js بـ target: "http://localhost:5000"، ومن بعد عاود npm run dev حيت كل تعديل على الملف كيجبّر restart.[6]

وآخر شي: فـ production ما كاين لا الـ Create React App server لا proxy — الـ browser كي prepend domain ديالك على الـ links و الـ requests كيمشي مباشرة للـ Express API، وهكذا الـ flow كيولي predictable بزاف.[7]

5 · ممارسة retrieval

جاوب من راسك قبل ما تclicki. ما تقدرش تحل حتى تجاوب — هادي هي القوة اللي كتبني memory.

1. ملّى كتكتب relative link بحال /auth/google من داخل React app ديال dev، فين كيمشي الـ request أصلا؟

الـ browser كي prepend domain اللي راه فيه دابا على أي relative link — و فـ dev هادا هو localhost:3000 (React server)، ماشي localhost:5000 (Express)، وهادي هي علّاش كتبان الـ redirect_uri mismatch.[4]

2. شنو المهمة ديال الـ proxy (setupProxy.js) فـ development؟

قاعدة وحدة: أي path من /api و /auth/google كيتصاوب ليه target هو http://localhost:5000 ومعاه نفس الـ path — الـ React server غير كيمرّر، والـ Express هو اللي كيخدم.[6]

3. فوق production (Heroku/Render)، شنو واقع مع الـ CRA server والـ proxy؟

فـ production ما بقيناش الـ Create React App server لا الـ proxy — الـ browser كي prepend domain ديالك والطلب كيوصل مباشرة للـ Express API، وهكذا الـ OAuth flow كيمشي بشكل أكثر predictability.[7]

4. مراجعة: من الدرس 6، كيفاش الكود كيعرف واش راه خدام فـ production؟

الجواب الصحيح هو process.env.NODE_ENV === 'production' — الكود كيفرق بين environment عن طريق هاد الـ variable، ماشي عن طريق scripts ولا URI. (قراية ديال retrieval: الـ variable هي هي اللي كتقرر يرجع prod.js ولا dev.js).
